# A3.1 — кадровый буфер: TS-Config → HDMI 720p50

2026-09-25. Исходники — [Firmware](../Firmware/README.md), верхний модуль `ts_fb_hdmi_top`.
Вторая прошивка видеотракта рядом с [генлоком](a3-fpga-video.md): выход тактируется
кварцем Tang, и развёртка — настоящий стандарт, а не «близко к стандарту».

## Что делает

| | Генлок (`ts_hdmi_top`) | Кадровый буфер (`ts_fb_hdmi_top`) |
|---|---|---|
| Выходной режим | 896×640, 28 МГц, 31,25 кГц, **48,83 Гц** | **1280×720p50 CEA-861** (VIC 19): 1980×750, 74,25 МГц, **50,000 Гц**; картинка на всю высоту, 4:3 или 16:9 (ниже). Сборка с HD = 0 — 720×576p50 (VIC 17/18) точка в точку |
| Источник выходного клока | PCLK Evo | кварц Tang 27 МГц |
| Задержка | меньше строки | до ~1 кадра (в среднем ~15 мс) |
| Если PCLK пропал | выход гаснет | развёртка идёт, держится последний целый кадр |
| Разница частот кадров | нет (выход = вход) | повтор кадра примерно раз в 42 кадра (0,85 с) |
| Память | 2 строки в BSRAM | 3 кадра в SDRAM (3,5 МБ) |

## Как устроен

```
PCLK 28 ─ PLL ×2 → 56 МГц: ts_mux_capture → fb_capture ─┐ async FIFO (256 × 33 бит)
кварц 27 ─ rPLL ×5 → 135 МГц TMDS                        ▼
            ├ CLKOUTD ÷2 → 67,5 МГц: fb_core ⇄ sdram_burst ⇄ SDRAM (3 кадра)
            └ CLKDIV ÷5  → 27 МГц: fb_scanout ← fb_line_ram (2 строки) → TMDS → HDMI
```

- **Захват** — тот же `ts_mux_capture`, что у генлока: две фазы мультиплексора → пиксель
  {PAL_SEL, B5, G5, R5}. `fb_capture` вырезает окно 720×576 и пишет в FIFO заголовок строки
  и пары пикселей. Палитра применяется только на выходе — в памяти ничего не теряется.
- **SDRAM** — свой контроллер `sdram_burst`: пакеты по 8 слов (32 байта), автопредзаряд,
  регенерация каждые 7,8 мкс. Имеющийся `sdram.v` побайтовый (~50 МБ/с) — для кадров мало;
  нужно ~82 МБ/с (запись 48,83 кадра/с + чтение 50 кадров/с).
- **Тройная буферизация** (`fb_core`): писатель пишет кадр в буфер W; целый кадр становится
  «последним готовым» L; вывод в начале каждого кадра берёт L. Писатель никогда не пишет
  в выводимый буфер, поэтому разрывов нет. Кадр со сбоем (пропущенные строки, обрыв
  PCLK) не публикуется.
- **Вывод** (`fb_scanout`): строка L запрашивается за две строки до показа (~37 мкс
  на выборку, реально нужно ~10–20 мкс), приходит в двухстрочный буфер.

## Масштаб 720p: ASPECT, SIZE и сглаживание

В 720p кадр Evo 720×576 растягивается по центру кадра 1280×720 (`fb_scanout`, SCALE). Два пункта
меню (кнопки Tang; LINK — CTRL биты 14 и 16:15; хранятся во flash Tang):

| SIZE \ ASPECT | 4:3 — пропорции сохраняются | 16:9 — на всю ширину |
|---|---|---|
| 100 % (по умолчанию) | 960×720 (x 160) | 1280×720 |
| 95 % | 912×684 (x 184, y 18) | 1216×684 (x 32, y 18) |
| 90 % | 864×648 (x 208, y 36) | 1152×648 (x 64, y 36) |

SIZE 95 и 90 % — для телевизоров, обрезающих края кадра (overscan): у старых LG «Just Scan»
для 720p нет, а кадр 720p с картинкой на всю высоту телевизор растягивает за края (на карте
видеозахвата те же 720 строк видны целиком). Все размеры делят 720 и 576 нацело.

**Сглаживание по площади.** Множители дробные (×1,25 по высоте, ×1,33 или ×1,78 по ширине), и
ближайшая точка давала точки Evo неодинакового размера («пикселизация»: строки по 2 и 3).
Теперь точка вывода берёт цвет тех точек Evo, которые она накрывает, пропорционально площади:
внутри точки Evo — чистый цвет, на границе — смесь в пропорции; на глаз все точки Evo
одинаковые, а размытия, как у билинейного масштаба, нет. Точка вывода k занимает
[k·N/D, (k+1)·N/D) точек источника (N/D = 720/ширина, 576/высота); если она заходит за границу,
вес следующей точки — (acc + N − D)/N, с шагом 1/16. Счётчики (DDA) ведут и номер точки, и acc.

Для этого буфер строк — четыре блока BSRAM (`fb_line_ram`): чётные и нечётные строки × чётные и
нечётные точки, на четыре строки; за такт читаются четыре точки 2×2. Строка Evo
запрашивается из SDRAM, когда она впервые понадобится строке вывода (как основная или как
нижняя для смешивания), за две строки до показа — по-прежнему одна строка за раз и один раз за
кадр, нагрузка на SDRAM та же (77 760 чтений за симуляцию, как без масштаба). Палитра — у каждой
из четырёх точек, смешивание по ширине и по высоте — двумя ступенями конвейера. Проверка
испытательной таблицы и калибровка SD READ сверяют исходную точку из памяти — работают в любом
масштабе. Смена ASPECT и SIZE вступает с нового кадра (геометрия защёлкивается за 4 строки до
его начала, до первых запросов его строк).

## Выход HDMI: AVI InfoFrame

`hdmi_tx` (в сборке 720p вместо DVI): преамбула и защитная полоса перед каждой активной строкой
(видео задержано на 10 тактов) и раз в кадр, по фронту VSYNC, островок данных с пакетом
AVI InfoFrame (CEA-861, версия 2): **RGB полного диапазона** (Q = 2), **компьютерный источник**
(ITC = 1) типа **«игра»** (CN = 3), **без обрезки** (S = 2, underscan), формат кадра 16:9,
VIC 19. Заголовок и подпакеты — с кодом BCH (1 + x⁶ + x⁷ + x⁸). В DVI телевизор решает сам:
принимает RGB за видео-диапазон 16–235 («переконтраст»), обрезает края, включает обработку.
Что из флагов выполнит конкретный телевизор — решает он. Старый LG пользователя флаги
ITC/«игра» не выполнил: яркость всего экрана «гуляла» по содержимому кадра — это его
подсветка и контраст по средней яркости, в сигнале Tang её нет (каждая точка выводится
независимо). Помогло в настройках телевизора: энергосбережение — выкл., режим изображения
«Эксперт»/«Кино», динамическая контрастность — выкл. (2026-10-16). Проверка — `tb/tb_hdmi_tx.sv`: поток разбирается по преамбулам, как в приёмнике
(`sh scripts/run_fb_sim.sh` его не запускает: `iverilog … rtl/tmds_encoder.sv rtl/hdmi_tx.sv
tb/tb_hdmi_tx.sv`).

## Экранное меню

40 × 21 знакоместо 16×16 точек (шрифт 5×7 ×2), с (IMG_X + 40, IMG_Y + 24) кадра. Фон — на
одно знакоместо шире текста со всех сторон, картинка под ним — 3/16 яркости с подсветкой синим.

Меню ведут кнопки Tang (S1 — пункт, S2 — значение) или регистр UI_KEY по LINK (с ядра 1.3):
те же нажатия плюс «предыдущий пункт», «показать» и «скрыть». Им пользуется плагин WC
[VDAC4 Video Settings](../../ESP32%20S3%20Zero%20N8R8/Network/Video%20Settings/README.md):
клавиши Evo через ESP (`TANG_WRITE`) идут в UI_KEY. Проверено в Evo: ядро 1.3, `vdac4-0.1.73`.

## Растры Evo и окно захвата

Графические режимы TS-Config (ZX, 16c, 256c, текст; 256/320/360 точек) меняют только
картинку внутри растра — захват их не различает и не должен. Растры разные
(HDL TS-Labs: `current/video/video_sync.v`, `base/video/video_sync_v.v`, `video_vga_sync_h.v`):

| Режим (`raster_detect`) | Строка VGA, отсчётов 28 МГц | Строк | HS | Кадр | На выходе 50,000 Гц | Окно H/V |
|---|---:|---:|---:|---:|---|---|
| 1 TS-Config Pentagon | 896 | 640 | 104 | 48,83 Гц | повтор раз в 0,85 с | 131 / 45 |
| 2 TS-Config `PENT_312` | 896 | 624 | 104 | 50,08 Гц | пропуск раз в ~12,5 с | 131 / 29 |
| 3 Base Conf Pentagon | 896 | 640 | 106 | 48,83 Гц | повтор раз в 0,85 с | 139 / 45 |
| 4 Base Conf 48k | 896 | 624 | 106 | 50,08 Гц | пропуск раз в ~12,5 с | 139 / 45 |
| 5 Base Conf 128k | 912 | 622 | 106 | 49,36 Гц | повтор раз в ~1,6 с | 139 / 45 |
| 0 незнакомый | любой | любое | — | — | — | по центру |

60 Гц (896×524, 59,64 Гц) не поддерживается — решение пользователя: в Base Conf это
вынужденный режим; такой растр захватывается как незнакомый.

**Автоопределение** (`rtl/raster_detect.sv`, домен захвата): полярность HS/VS — активен
более короткий уровень; длина строки, число строк и ширина строчного импульса. TS-Config
и Base Conf на одном растре различаются шириной HS (104 и 106 отсчётов). Растр считается
захваченным после трёх одинаковых кадров. Каждый кадр получает отметку «целый»: в конце кадра
в FIFO уходит служебное слово, и писатель публикует кадр только с этой отметкой — кадр, во
время которого растр сменился, на экран не попадает. Смена растра не прерывает развёртку
576p50: пока растр перезахватывается (~3 кадра, 60 мс), держится последний целый кадр.

**Окно захвата.** Смещения таблицы — расчётные: TS-Config Pentagon — прежние значения
генлок-тракта; остальные — разницей по HDL (`PENT_312` видимая часть на 16 строк VGA раньше;
Base Conf картинка на 8 отсчётов дальше от HS, начало видимой части одно для трёх растров).
К ним прибавляются поправки `h_adj`/`v_adj` от ESP.

**Автоподстройка по картинке** (`rtl/active_bbox.sv` + `raster_detect`). Режим 360×288
занимает всю видимую область — запаса бордюра нет, окно должно стоять точно до точки.
`active_bbox` за каждый кадр находит границы не чёрной картинки в координатах окна. Если
ширина найденной картинки ровно 720 (высота ровно 576), положение повторилось три кадра
подряд и отличается от профиля не больше чем на 16, окно встаёт по картинке. Это срабатывает
в режиме 360×288 и в любом режиме с цветным бордюром; чёрный бордюр ничего не сбивает.
Применяется только там, где видимая область Evo равна окну: TS-Config и Base Conf Pentagon —
по обеим осям, Base Conf 48k — только по горизонтали (видимых строк 560), 128k — нигде
(видимая область 736×558). Границы картинки выведены наружу — ESP сможет показывать их
и управлять подстройкой сам.

## LINK: настройки и состояние для ESP

Ведомый QSPI — [fb_link.sv](../Firmware/rtl/fb_link.sv): команда 8 бит по IO0, адрес 32 бита
по IO0…IO3, для чтения 8 тактов разворота, данные словами по 32 бита старшим байтом вперёд;
0x01 — запись, 0x02 — чтение. Сдвиговые регистры тактируются самим LINK_SCK (FPGA77, GCLKT_1).
Карта регистров — комментарий в [ts_fb_core.sv](../Firmware/rtl/ts_fb_core.sv):

| Адрес | Регистр | |
|---|---|---|
| 0x00 | ID | `56444334` («VDC4») |
| 0x04 | VERSION | личность 01, протокол 01, версия 1.3 (1.1 — flash Tang и поправки по растрам; 1.2 — ASPECT и SIZE; 1.3 — UI_KEY) |
| 0x08 | STATUS | растр, режим, полярности, окно, SDRAM, калибровка; [31:16] PCLK, кГц |
| 0x0C…0x24 | RASTER, SYNC, WINDOW, PIC_X, PIC_Y, FRAMES, CHECK | измерения захвата |
| 0x3C | SCRATCH | проверка канала |
| 0x40 | CTRL | источник, MUX PHASE/DELAY/CLOCK, AUTO ALIGN, SD READ, меню, запуск калибровки |
| 0x44 | ADJUST | H/V ADJUST со знаком — текущего растра |
| 0x48 | FLASH_CMD | мост к flash: передать N байтов буфера, принять M, держать CS |
| 0x4C | FLASH_STATUS | мост занят; настройки прочитаны / найдены; ячейка; первая чистая ячейка |
| 0x50 | UI_KEY | нажатие для экранного меню, только запись: 1 — следующий пункт, 2 — предыдущий, 3 — значение +1, 4 — −1, 5 — показать меню, 6 — скрыть |
| 0x60…0x7C | ADJ_TAB | H/V ADJUST растров 0…7 (режим `raster_detect`) |
| 0x80…0xBC | FLASH_BUF | буфер моста, 64 байта |

Запись по LINK меняет те же настройки, что и кнопки Tang (у LINK приоритет). Поправка окна
своя у каждого растра: при смене растра (TS-Config ↔ Base Conf, Pentagon ↔ 48k) действует
поправка нового.

**ESP** ([tang_link.cpp](../../ESP32%20S3%20Zero%20N8R8/Firmware/src/tang_link.cpp),
[link_spi3.cpp](../../ESP32%20S3%20Zero%20N8R8/Firmware/src/link_spi3.cpp), с 0.1.63) — аппаратный
SPI3 без драйвера ESP-IDF: `spi_bus_initialize()` в этой прошивке вешает ESP внутри
`spicommon_bus_initialize_io()` (пробы 0.1.54–0.1.61 на столе); тактирование, сброс и выводы
через матрицу GPIO делаются своим кодом, транзакции ведёт `spi_hal_*` опросом.
При запуске Tang ищется на 1 МГц, затем выбирается самая высокая частота из 40 / 26,7 / 20 / 13,3 /
10 / 5 МГц, на которой 1000 проверок (запись и чтение SCRATCH, чтение 16 слов со сверкой ID,
версии и SCRATCH) проходят без ошибок; при запаздывании ответа ESP добавляет 1–2 такта разворота.

Проверено на столе (Tang от USB, плата без Evo, 0.1.63): **40 МГц, 8 тактов разворота, 0 ошибок
из 2000**; 1000 чтений по 64 байта — 21 мс (~3 МБ/с вместе с накладными расходами на транзакцию).

LINK запускается, когда запитана плата (линия CS: R10 к шине логики) или сама Tang (LINK_IRQ_N:
подтяжка 10 кОм на модуле Tang). Питание платы ESP определяет по напряжению CS через АЦП:
у Tang, запитанной от USB, линию приподнимает её светодиод на FPGA18 (на столе 1,5 В с подтяжкой
ESP вниз против ~2,7 В от R10), и логический уровень там обманчив — до 0.1.63 ESP в таком
состоянии запускала I2S в обесточенный ЦАП.

Сетевая консоль ESP (порт 23, `tools/net_console.py`): `tang` — сводка STATUS…CHECK и
расшифровка CTRL/ADJUST, `tang rd АДРЕС`, `tang wr АДРЕС ЗНАЧЕНИЕ` (hex). Изменения состояния
и настроек Tang ESP пишет в журнал наладки раз в 2 с.

## Настройки во flash Tang

Flash Tang Nano 20K — XTX XT25F64B (JEDEC `0B4017`, 8 МБ) на выводах MSPI ПЛИС (MCLK 59, MCS_N 60,
MO 61, MI 62; после загрузки ПЛИС — обычные выводы, `use_mspi_as_gpio`). Модуль
[fb_flash.sv](../Firmware/rtl/fb_flash.sv), SCK 18,6 МГц:

| Адрес flash | Что |
|---|---|
| 0x000000…0x0DD89A | прошивка Tang: упакованный `.fs`, ровно то, что пишет Gowin Programmer (сверено побайтно) |
| 0x7FF000, 4 КБ | настройки: 128 ячеек по 32 байта; MAGIC «VDST», MUX CLOCK/DELAY/PHASE, AUTO ALIGN, H/V ADJUST восьми растров, сумма |

- **Загрузка — самим ядром**: через ~1 мс после сброса оно читает сектор до первой чистой
  ячейки и берёт последнюю целую (недописанная при пропадании питания не проходит по сумме).
  Источник и SD READ не хранятся: источник после включения всегда AUTO, SD READ калибруется.
- **Запись — через ESP** ([tang_flash.cpp](../../ESP32%20S3%20Zero%20N8R8/Firmware/src/tang_flash.cpp),
  с 0.1.64): раз в 2 с ESP читает CTRL и ADJ_TAB; изменение, державшееся с прошлого опроса,
  уходит в следующую ячейку (с чтением обратно); когда ячейки кончились — сектор стирается.
  Пишет только при живом ядре: ID и версия сверяются до и после чтения настроек — пока Tang
  грузится (~3 с), LINK читает мусор с подтяжек. Перед каждой командой flash буфер моста
  читается обратно.
- Проверено на столе (0.1.65–0.1.67): настройки, изменённые по LINK, записаны в ячейку 0,
  после перезагрузки Tang (Reprogram) ядро загрузило их само; рабочие значения
  (PHASE 1, DELAY 1, CLOCK B, поправки 0) записаны в ячейку 1.

## Обновление прошивки Tang через ESP

`python tools/tang_tool.py update <IP ESP> "../../Tang Nano 20k/Firmware/firmware/ts_fb_hdmi_top.fs"`
(из `ESP32 S3 Zero N8R8/Firmware`; порт 8268 ESP, с 0.1.65). ESP принимает образ целиком в PSRAM и проверяет SHA-256,
слово синхронизации A5C3 и IDCODE GW2AR-18 `0000081B` в заголовке и что образ кончается до
блока с настройками (0x7F0000); затем стирает блоки 64 КБ, пишет и читает обратно для сверки.
Новое ядро Tang загружает при следующем включении питания (Evo выключить и включить; на столе —
Reprogram в Gowin Programmer). Проверено на столе: 907 418 байт за 8 с, сверка совпала, Tang
загрузилась с записанного. Каждое следующее ядро обязано сохранить мост к flash (регистры
0x48/0x4C/0x80) — иначе обновлять Tang придётся снова по USB.

Порт 8268, как и консоль 23, открыт в локальной сети без пароля.

## Чем проверено

Масштаб (тестбенч `tb_ts_fb`, ASPECT = 0 и 1, `sh scripts/run_fb_sim.sh hd [1]`): каждая точка
выхода сверяется с точкой источника по точной формуле ⌊x·720/W⌋, ⌊y·576/720⌋; поля вокруг
картинки — чёрные. Режим точка в точку (уменьшенные растры, сборка HD = 0) — прежние сценарии.

Тестбенч [tb_ts_fb.sv](../Firmware/tb/tb_ts_fb.sv): модель растра Evo (любой из таблицы,
смена на лету, любая полярность, сдвиг картинки) → мультиплексор с задержкой 4,5 нс → тракт →
**модель SDRAM с проверкой протокола** ([sdram_model.sv](../Firmware/tb/sdram_model.sv):
tRCD, tRP, tRC, tRAS, tWR, tRFC, регенерация, открытая строка, конфликт шины) →
**декодер TMDS**: выход проверяется так, как его увидит монитор. Номер входного кадра
закодирован в строке 0, а картинка от него зависит — склейка двух кадров ловится сразу.
Три тактовых генератора независимы, как на плате. Icarus Verilog 13.0.

Настоящие размеры, картинка — экран ZX «Hibernated 1» в синем бордюре

## Синтез в Gowin 1.9.11.03 Education

`gw_sh scripts/gowin_fb.tcl` — битстрим собирается, ограничения выполнены:

| Ресурс | Занято | Доля |
|---|---:|---:|
| Логика (LUT + ALU) | 1 888 из 20 736 (1 350 LUT, 472 ALU) | 10 % |
| Триггеры | 1 043 | 7 % |
| BSRAM | 3 из 46 | 7 % |
| rPLL | 2 из 2 | 100 % |

| Домен | Нужно | Fmax после раскладки |
|---|---:|---:|
| SDRAM и кадры | 67,5 МГц | 110,8 МГц |
| Пиксели | 27 МГц | 96,4 МГц |
| Захват (с автоопределением) | 56 МГц | 87,3 МГц |

Генлок-прошивка (`scripts/gowin_genlock.tcl`) после тех же исправлений тоже собирается:
515 LUT, 2 BSRAM, пиксельный домен 85 МГц при нужных 28.

По ходу первой настоящей сборки найдены и исправлены ошибки, которые прятались, пока
проект проверялся только симуляцией и Yosys (касаются и генлок-прошивки):

- `IO_TYPE=LVDS25` на выводах HDMI недопустим для эмулированного LVDS — нужен `LVCMOS33D`;
- в `async_fifo` признак «полон» образовывал комбинационную петлю — стал регистром;
- Gowin не принимает перенос строки через `\` в SDC;
- объявление `wire a, b, gnd = 1'b0;` Gowin отвергает — разнесено;
- макрос `SYNTHESIS` в Gowin задать нечем, поэтому смысл перевёрнут: заглушки для симуляции
  включаются макросом `SIMULATION` (`-DSIMULATION`), синтез по умолчанию берёт примитивы.

## Что проверить на железе

- Фазу клока SDRAM (сейчас — инверсия клока логики) и `RD_LAT` в `sdram_burst`.
- Примет ли монитор 576p50 по HDMI/DVI (часть ПК-мониторов 576p не принимает).
- Всё, что перечислено для генлока: `SAMPLE_DELAY`, `SEL_PHASE`.
- Смещения окна для каждого растра — программой 360×288 с рамкой по краю или с цветным
  бордюром (автоподстройка покажет разницу с таблицей; её стоит перенести в таблицу).
- Ширину HS у TS-Config и Base Conf (104/106) — от неё зависит различение конфигураций.
- Регенерация SDRAM сделана по 7,8 мкс (8192/64 мс) — вдвое чаще, чем нужно микросхеме
  на 4096 строк; запас оставлен сознательно.
