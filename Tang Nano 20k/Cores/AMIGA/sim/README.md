# Симулятор Amiga / VDAC4

Запуск: **`Amiga Simulator.cmd`**. Панель открывается по адресу
**http://127.0.0.1:8088**. OBS и подключённая плата не требуются.
Панель доступна только с этого компьютера.

Выберите «Эталон 0.11» или «Текущие исходники», укажите ROM и при необходимости
ADF/HDF, затем нажмите «Собрать и запустить». Сборки кешируются по хешам исходников.
При изменении только хостовой программы повторно компилируется только она;
объекты RTL используются повторно лишь при полном совпадении HDL, инструментов
и параметров компиляции. Последний сеанс сохраняется при перезапуске панели.
Эталон хранится отдельно в `reference/0.11`; его файлы защищены проверкой SHA-256.
Текущие исходники берутся из родительского проекта AMIGA.

Это **RTL-симулятор для отладки, существенно медленнее реального времени**.
На данном компьютере кадр занимает примерно минуту или больше, в зависимости
от профиля и нагрузки. Штатные четыре кадровых импульса сброса сохранены:
первые примерно 80 мс Amiga тоже нужно просимулировать. В панели отдельно
показаны виртуальное время и время компьютера. Это не игровой эмулятор.

## Управление

- Два изображения: внутренний RGB и кадр, восстановленный из последовательных
  TMDS-линий после настоящих OSER10 и выходных буферов. RGB отдельно не считается
  доказательством исправности HDMI.
- Пауза, продолжение, шаг на кадр, сброс Amiga, остановка.
- Клавиатура передаётся после щелчка по изображению HDMI. Для движения мыши
  удерживайте среднюю кнопку; левая и правая кнопки передаются в Amiga.
- «Проверка OSD через QSPI» выводит диагностическую надпись через текстовую память
  настоящего оверлея. Это проверка тракта OSD, а не исполнение меню AMIGA.ELF.
- Настройки масштаба в панели пишут регистр изображения новых исходников.
  У эталона 0.11 этого регистра нет.
- Можно снять регистры LINK и ограниченный VCD на 10 мкс. Трасса CPU сохраняется
  постоянно: первые 128 циклов — `boot.csv`, последние 4096 — `cpu.csv`.

Быстрый старт заполняет модель SDRAM из ROM и проверяет все 512 КБ перед
освобождением CPU. Он **не проверяет загрузчик ROM**. Для полного прогона снимите
флажок: тогда весь ROM передаётся через настоящий QSPI и загрузчик FPGA,
с проверкой подтверждений блоков, CRC и содержимого SDRAM. Это заметно дольше.
В быстром режиме сброс моделируется импульсом ROM-ready; в полном — командой LINK.

ADF/HDF обслуживаются через настоящий дисковый ящик FPGA и QSPI. Образы открываются
для чтения; гостевые записи идут в файлы `unit*.cow` внутри сеанса. Оригинальные
образы не изменяются. WAV содержит PCM Paula до нормализации на ESP.

## Автоматические прогоны

В PowerShell, находясь в этой папке:

```powershell
$py = 'E:\zx\esp\pio-venv\Scripts\python.exe'
& $py -X utf8 .\check_clocks.py --profile current
& $py -X utf8 .\check_clocks.py --profile current --negative
& $py -X utf8 .\check_memory.py --profile current
& $py -X utf8 .\check_memory.py --profile current --negative
& $py -X utf8 .\check_config.py --profile current
& $py -X utf8 .\test_controls.py
& $py -X utf8 .\regress.py --profile current
& $py -X utf8 .\run.py run --profile stable --fast-rom --seconds 0.13
```

Отрицательные проверки возвращают успех только при обнаружении намеренно
внесённой ошибки. `check_clocks --negative` возвращает прежний отсутствующий
сброс CLKDIV. `check_memory --negative` проверяет исходное задержанное присваивание
модели Gowin в Verilator 5.050, которое даёт неверную фазу.

`regress.py` использует небольшой собственный диагностический ROM, создаваемый
`diagnostic_rom.py`: чтение/запись RAM, проверка результата и цветные полосы.
При ошибке RAM программа останавливается на пурпурном фоне. Регрессия требует
все четыре цвета и правильные начальные чтения CPU; один цвет ошибкой не маскируется.
Этот ROM не содержит Kickstart и не является заменой Amiga OS.
Его прогон по умолчанию длится 0.16 с виртуального времени, чтобы дождаться
полного цветного кадра после кадрового буфера.

`run.py run --rom ... --adf ... --hdf ... --hdf1 ... --seconds ...` запускает
произвольный набор образов без браузера. Без `--fast-rom` используется полный
загрузчик QSPI. Время задаётся **после загрузки ROM**. Прогон 0.13 с проверяет
выход CPU из сброса и начало исполнения, а не полную загрузку Workbench/Test Kit.

Артефакты находятся в `runs/<сеанс>/`: изображения PPM, WAV, CSV, журналы,
проверки тактов/памяти и манифест хешей. VCD открывается в совместимом просмотрщике.
Пользовательские ROM не входят в эталон; при быстром старте приватная hex-копия
создаётся только внутри исключённой из git папки `runs`.

## Что именно моделируется

Полный верхний модуль FPGA, свежая трансляция VHDL TG68K с теми же generic-параметрами,
настоящий SDRAM-контроллер, память 8 МБ, загрузчик ROM, QSPI, дисковый ящик,
видеотракт и сериализатор. Старая готовая Verilog-трансляция CPU не используется.
CPU-wrapper выбирает аппаратную ветку, включая berr и skipFetch.

Для SDRAM используются явные задержки: такт до вывода 4971 пс, команда/данные
записи 5043 пс, входные данные 1853 пс и tAC 6000 пс. Это модель выбранных
задержек, а не проверка всех маршрутов и электрических допусков платы.

Перед запуском выполняется отдельная четырёхсостоянийная проверка ФАПЧ/CLKDIV/OSER10
в Icarus на моделях установленного Gowin. Память проверяется в двух симуляторах:
совпадение фазы, чтение, запись, сохранение байтов при масках.

Профиль `current` также проходит `check_sdram_startup.py`: требования W9864G2GH
к начальной паузе, DQM, PRECHARGE ALL, восьми AUTO REFRESH и MRS проверяются
по внешним выводам. Эталон 0.11 сохраняется без изменений и служит отрицательным
контролем этой проверки (`--profile stable --expect-reject`).

Отдельный тест арбитража из корня проекта:
`python tests/run_cpu_video_memory.py --saturated-video`. Он не даёт видеоклиенту
искусственных пауз и требует ответа CPU за 600 тактов SDRAM. Отсутствие порчи
данных и положительный суммарный счётчик CPU не исключают голодание шины.

Для Verilator 5.050 статический выход ФАПЧ 270°/50% выражен эквивалентной формой:
инверсия такта с задержкой на четверть периода. Без адаптера перенос задержанного
присваивания vendor-модели сдвигает фазу на полпериода. Icarus исполняет исходную
vendor-модель. В проверке памяти временные метки обоих вариантов должны совпасть.
Сам файл Gowin и RTL проекта не изменяются; адаптер создаётся в папке сборки и
отражается в манифесте. Версия и хеш VHDL-фронтенда также записываются.

На тактовой паре TMDS и всех трёх парах данных требуется **DRIVE=4**.
Это проверяется при запуске сборки симулятора и перед `run all` в `build.tcl`.
`prepare.py` закрепляет значение 4 при генерации CST и сохраняет проверку в TCL.
Саму электрическую силу драйвера RTL-симуляция не воспроизводит.

ESP32/BL616 здесь представлены хостовой моделью протоколов; их двоичные прошивки
не исполняются. Меню AMIGA.ELF, его F11/F12, кеш менеджера ядер и нормализация ESP
этим прогоном не проверяются. Физические SD SPI/Evo и файловая система Tang SD
не моделируются. RTL моста SD сохранён. Электрические помехи HDMI/SDRAM,
временная сходимость размещённой FPGA и совместимость конкретного видеозахвата
требуют аппаратной проверки.

## Зависимости

На этом компьютере пути уже настроены в `build.py`: Verilator/Icarus из
`E:\zx\tools\rtl\ucrt64`, Gowin 1.9.11.03 Education, MSVC 14.44, Windows SDK
10.0.26100.0, Python и Pillow. `setup.py` проверяет их и устанавливает локальный
GHDL 6.0.0 из официального архива с проверкой SHA-256. Сборка ведётся в ASCII-пути
`E:\zx\cache\tmp\amiga-simulator`, чтобы не зависеть от поддержки Unicode
в инструментах HDL. Прошивка платы и файлы на её SD при работе симулятора не меняются.
