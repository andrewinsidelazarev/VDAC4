# Amiga / AGA на VDAC4

Ядро Amiga с чипсетом AGA для **Tang Nano 20K + ESP32-S3 + BL616**. Основа —
[NanoMig](https://github.com/MiSTle-Dev/NanoMig), зафиксированный commit
`acebbd9e3709ee5d7ca34f1a6b491a4cad369494`.

Версия **0.13.7, слой ESP 0.26**. Образы — в [`../SD/CORES`](../SD/CORES); `AMIGA.BIN` и `AMIGA.ELF` ставятся только вместе.

**Образы дисков, записанные ядром до 0.10, могут быть испорчены.** Пока дискета работала вместе с диском, в файлах появлялись нулевые
сектора. Такой образ лучше создать заново и поставить систему ещё раз.

## Что внутри

| Узел | Реализация |
|---|---|
| Процессор | TG68K, режим 68020, кэш CPU; команды из chip RAM тоже идут через кэш (турбо chip RAM) |
| Чипсет | AGA, PAL/NTSC, 2 МиБ chip RAM + 4 МиБ fast RAM |
| Видео | HDMI 720×576 50 Гц (PAL) или 720×480 60 Гц (NTSC), RGB888, окно DIW находится само |
| Звук | Paula → LINK → ESP32 → общий нормализатор TRACKER → ЦАП VDAC4 |
| Клавиатура, мышь, джойстик | Evo → плагин WC → ESP32 → LINK → Amiga; джойстик — в игровой порт 2, можно с клавиатуры |
| Дискета DF0 | образы ADF 880 КиБ, выбор и смена на ходу в меню F11, запись в образ |
| Жёсткий диск | IDE, образ HDF с RDB; образ работает на месте, без копирования |
| Карта Evo | второй диск IDE: ESP читает FAT16/FAT32 карты и показывает Amiga том FFS `EVO:`, только чтение |
| Часы | RTC получает время от Evo |

Меню F11: вкладки TANG, EVO, NET, HDD, KEYS и SETUP. INS создаёт новый образ дискеты или диска в текущей папке, на вкладке HDD Enter
делает диск системным, Del снимает его. На вкладке NET — архив archive.org по разделам (игры, демо, музыкальные диски, слайд-шоу,
дискмаги, прикладные программы, Fred Fish, Workbench и другие); скачанное ложится в `/Amiga/<раздел>/Downloads/` на карте Tang
(игры — в `/Amiga/Games/Downloads/`). Вкладка KEYS — клавиатура как джойстик, см. ниже.

## F11 → KEYS: клавиатура как джойстик

Вкладка KEYS делает из клавиатуры джойстик игрового порта 2 (его читают игры).

- Первая строка **KEYBOARD AS JOYSTICK**: Enter включает и выключает режим. По умолчанию он выключен.
- Строки UP, DOWN, LEFT, RIGHT, FIRE 1, FIRE 2 — клавиши действий. Enter на строке — значение мигает, нажмите новую клавишу.
  Клавиша, уже назначенная другому действию, меняется с ним местами. Esc и F11 отменяют выбор; Esc, F11 и F12 назначить нельзя.
- Del возвращает назначения по умолчанию: стрелки, FIRE 1 — левый Ctrl, FIRE 2 — левый Alt.
- Настройка сразу сохраняется в `/AMIGA/KEYS.CFG` на карте Tang и действует при следующих запусках.

**Пока режим включён, назначенные клавиши уходят только в джойстик: Amiga не получает их как нажатия клавиатуры.** Тест
клавиатуры Amiga Test Kit их не засчитает, и набрать эти символы нельзя. Если назначены буквы (например, Q, A, O, P и M), для
набора текста выключите режим. Остальные клавиши работают как обычно.

## F11 → SETUP

- **PICTURE SIZE:** 100 %, 95 % или 90 %. Для телевизоров, которые режут края (старому LG нужно 95 %). Хранится в `/AMIGA/VIDEO.CFG`.
- **COMPATIBILITY:** OFF или 68000, NO FAST RAM — для старых демок и игр под A500: процессор 68000 (кадры исключений 68000, адрес
  24 бита), без fast RAM и без турбо. Режим берётся при запуске Amiga: после смены меню спрашивает перезапуск, Enter загружает ядро
  и ROM заново. Хранится в `/AMIGA/MODE.CFG`. Kickstart для A1200 в этом режиме может не загрузиться — тогда выключите режим.

## Видео

Кадр Amiga записывается в SDRAM (RGB888, область `0x600000–0x7367FF`) и выводится в 576p/480p, независимо от растра чипсета:
пиксельная частота 27 МГц, TMDS 135 МГц, выводы TMDS — `DRIVE=4`. Окно DIW определяется по сигналам чипсета, чёрные точки картинки
для этого не используются. Дисплею сообщается формат 16:9 (флаг AVI); точки те же. Interlace собирается из двух полей, все 512 строк.

Видео пользуется слотами SDRAM, где нет обращения чипсета. Когда захват или вывод отстаёт, процессор придерживается на chip RAM, а
блиттер (с 0.13.6) пропускает каждый второй свой слот; решение меняется только на границе слота, поэтому блиттер и шина видят одно и
то же. Без этого при широком оверскане и блиттере в «злом» режиме (финальные титры Nexus 7) захват не успевал записать половину
строки, и на экране оставалась половина строки прошлого кадра — тонкие полосы.

С 0.13.7 захват пишет в SDRAM каждую строку, где окно DIW есть в этом кадре (прежде — только строки окна прошлого кадра плюс-минус
две строки), и вывод выбирает буфер кадра без разрыва. Буферов два, Amiga даёт кадр за 19,968 мс, вывод — за 20,000 мс; если захват
текущего кадра уже ниже верха окна, вывод берёт этот кадр, иначе последний готовый. Без этого у окна, которое двигается по вертикали
(шар в Nexus 7), край показывался из прошлых кадров, а в части фаз низ кадра брался из соседнего кадра (финальные титры Nexus 7).

## Турбо chip RAM (0.13.5)

Команды из chip RAM процессор берёт через свой кэш, как кэш команд 68020 у A1200; данные идут по шине чипсета, как прежде. Все
записи chip-шины — процессора и DMA (блиттер, диск) — обновляют кэш, поэтому код, который демка распаковывает или правит, исполняется
в новом виде. Кэш включается битом EI регистра CACR, как у 68020 (Kickstart и демки его ставят). Без турбо демки с кодом в chip RAM
не успевали: Nexus 7 (Andromeda) застревал на первой сцене, а процессор тратил на выборку почти весь кадр шины. В режиме
совместимости турбо выключено.

## Нормализация звука в ESP

К потоку Paula 48 кГц добавлен общий `zm_level.h` из TRACKER.ELF: цель −12 LUFS, шаг изменения усиления до 0,5 дБ/с, мягкое
ограничение пиков. Тишина не повышает усиление. FPGA и каналы Paula этой обработкой не изменяются.

## Что нужно

- Прошивка ESP **vdac4-0.1.119** или новее (ABI 1.12; опубликована 0.1.121), BL616 **38** или новее, TS-Config 1.30 или новее,
  плагин WC **VDAC4 Cores 0.15** или новее (с 0.14 Amiga работает, но без тома `EVO:`). `AMIGA.BIN` и `AMIGA.ELF` ставятся только
  вместе: ELF проверяет версию ядра.
- **Kickstart — свой.** ROM в репозитории нет и не будет: это чужая защищённая авторским правом
  программа. Нужен файл на 512 КиБ с правильной контрольной суммой Amiga. Проверялся
  Kickstart 3.1 40.63 для A500/A600/A2000 (MD5 `e40a5dfb3d017ba8779faba30cbd1c8e`). Он есть в
  [списке проверенных ROM NanoMig](https://github.com/MiSTle-Dev/NanoMig/blob/main/doc/KICKSTART_ROMS.md).
  Чипсет AGA задаётся конфигурацией ПЛИС, а не названием ROM; для совместимости с программами A1200
  лучше Kickstart 3.1 40.68 (он на плате ещё не проверен).

## Установка

Раскладка на microSD Tang:

```text
CORES/AMIGA.BIN
CORES/AMIGA.ELF
AMIGA/KICK31.ROM   ваш Kickstart, переименованный
AMIGA/DF0.ADF      необязательно, образ дискеты 901120 байт
AMIGA/HD0.CFG      создаётся меню: путь к системному диску
```

`AMIGA.BIN` и `AMIGA.ELF` лежат в [`../SD/CORES`](../SD/CORES). В [`../SD/AMIGA/DF0.ADF`](../SD/AMIGA/DF0.ADF) — свободный
[Amiga Test Kit 1.21](https://github.com/keirf/amiga-stuff/releases/tag/testkit-v1.21) Кейра Фрейзера;
с него удобно начать.

В WC откройте плагин **VDAC4 Cores** и выберите AMIGA. ESP проверит ROM и образ дискеты, загрузит ядро
и передаст ROM в SDRAM. Без дискеты появится экран Kickstart, с дискетой запустится её программа.
Дискеты и диски меняются в меню F11.

| Клавиша | |
|---|---|
| F11 | меню дискет, дисков и настроек |
| Ctrl+Alt+F4 | тёплый сброс Amiga |
| F12 | выход в WC |

## Карта Evo в Workbench

Карта Evo подключается вторым диском IDE и монтируется Kickstart сам, томом `EVO:`. Workbench 3.1 читает FAT только через CrossDOS
40 (FAT12/16), а карта Evo — FAT32; поэтому FAT разбирает ESP и отдаёт Amiga готовый том FFS, собранный на лету. Карта при этом
никогда не пишется:

- файлы и папки защищены от записи и удаления, свободного места на томе нет — новые файлы не создаются;
- если Workbench всё же перепишет свой блок (переименование, значок), блок остаётся в памяти ESP до выхода из ядра;
- длинные имена FAT; кириллица — латиницей (`Щука.txt` → `Schuka.txt`), прочие знаки не из ASCII — `_`; имя не длиннее 30 знаков,
  расширение сохраняется, совпавшие имена получают `~1`, `~2`;
- первый раздел FAT16 или FAT32 карты (или карта без таблицы разделов); FAT12, exFAT и GPT не поддерживаются;
- архив `.lha` или `.lzh` (слой 0.19) — и файл, и папка рядом с тем же именем без расширения: в ней файлы и папки
  архива, распакованные на лету. LhA на Amiga не нужен: `Install` из такой папки запускается двойным щелчком, файлы
  копируются на HD01 как обычные. Заголовки уровней 0–2; методы lh0, lh1 (старые архивы LHarc), lh4–lh7; члены с другими
  методами не показываются. Сжатый файл распаковывается по мере чтения, проверяется CRC-16 архива. Проверено на ПК на
  настоящих архивах Aminet (HippoPlayer, ReqTools: 72 файла, всё совпало с 7-Zip) и на модели ядра с Kickstart 3.1;
- папка читается с карты, когда Amiga впервые к ней обращается; сектора читает Z80 Evo, поэтому том заметно медленнее карты Tang.

Нужен плагин VDAC4 Cores 0.15: он читает сектора карты в ответ на запросы ESP. Без него (или без карты в Evo) тома нет, Amiga
работает как раньше.

Kickstart не ищет диски после того, у кого в RDB стоит флаг «последний диск», а он стоит у образов, созданных в меню F11. Пока
том EVO подключён, ESP показывает Amiga RDB системного диска без этого флага; сам файл образа не меняется.

На модели ядра (`tests/run_evo_boot.py`) настоящий Kickstart 3.1 загрузился с тома, собранного этим же кодом из FAT, смонтировал
`EVO:`, `Type` вывел файлы с него, `Dir` — список корня с именами латиницей. Независимая проверка тома (`tests/check_evo.py`)
сверяет каждый файл тестовых образов FAT16 и FAT32 по содержимому, имени и дате.

финальных титров больше нет сдвинутых сегментов. Тест клавиатуры Amiga Test Kit засчитал все клавиши, кроме назначенных джойстику.

9 ноября 2026, 0.13.6 и ELF 0.26, ESP vdac4-0.1.122, BL616 41, TS-Config 1.46:

- демо Nexus 7 (Andromeda, AGA) идёт целиком: сцены сменяются по музыке (на 0.13.4 и раньше крутилась только первая сцена),
  финальные титры без полос («Всё хорошо»). На 0.13.5 титры показывали полосы на половину строки; причина воспроизведена в полном

8 ноября 2026, 0.13.1 (576p, без второго обращения SDRAM для видео): развёртка держится под нагрузкой в Workbench; старому LG нужен
размер 95 %. Режим совместимости (0.13.3) загружает Kickstart 3.1 A500; переключение режима сделано перезапуском сеанса (ELF 0.26).

Ещё не проверено: Kickstart 3.1 40.68 и Kickstart для A1200 в режиме совместимости, запись на дискету, долгая работа.


1 ноября 2026, 0.10 и ELF 0.14, ESP vdac4-0.1.120, BL616 38:

- Workbench 3.1 поставлен с шести дискет на новый образ HDF 1 ГиБ. Файлы образа сверены с дискетами: 342 файла, нулевых секторов нет,

  (похоже на сохранённые Workbench положения значков), `/Disk.info` — на 229 байт и по размеру; по байтам они не разобраны;
- ядро 0.9 с той же прошивкой: Workbench загружался с жёсткого диска, работали мышь и клавиатура, сигнал Test в Prefs → Sound слышен,
  дискета с archive.org скачалась на карту.

Ещё не проверено: запись на дискету, загрузка и работа Workbench на самом ядре 0.10, Kickstart 40.68, игры и долгая работа.
На плате: том `EVO:` подключается (значок в Workbench, слой 0.18, 2 ноября); чтение файлов с него, архивы как папки (0.19)

2 ноября 2026, слой 0.19: при копировании значков Amiga без ошибки вышла в WC, в журнале ESP причины нет. Вероятная причина (на плате не подтверждена) — гонка в

## Как устроена память

SDRAM работает на 85,5 МГц, CAS 2. Контроллер работает по спаду `clk85` и совпадает по фазе с `clk28`,
регистры DQ стоят в I/O по фронту, такт SDRAM (`CLKOUTP`) идёт на 90° после рабочего фронта
контроллера. Это важно: такт доходит до вывода примерно на 5 нс позже внутреннего фронта, и при 180°
данные читались на самом краю окна. Подробности и снятые на плате трассы описаны в
[diagnostics.md](diagnostics.md).

Данные SDRAM принимаются через промежуточный регистр `dq_r` по разрешениям, посчитанным на такт раньше: на полутакте остаются только этот
регистр и 16 бит `dout` чипсета. Запас приёма 2,09 нс; сборки с запасом меньше 0,5 нс на плате давали красный экран Kickstart.

## Обмен с дисками

Дискета и диск идут через один ящик `fpga/amiga_disk.sv`, он обслуживает один запрос за раз; при одновременных запросах первым идёт диск.
Ящик сообщает, кого обслуживает (`served_ide`), и у IDE и дискеты своя занятость. Без этого обмен дискеты сдвигал указатель буфера IDE,
и на диск ложились нулевые или сдвинутые сектора. Проверка на модели — `tests/run_ide_floppy.py`.

## Сборка

Исходники ядра — `fpga/` (правки VDAC4 поверх NanoMig) и неизменённые файлы NanoMig в `upstream/`; `build.tcl` — проект Gowin.
Образ собирается так (выпуски — раскладкой 2, сборка идёт в отдельной копии, рабочие файлы не меняются):

```
python build.py fpga --place-option 2
```

Нужен Gowin 1.9.11.03, устройство `GW2AR-LV18QN88C8/I7`, revision C. В `upstream/` лежат только нужные для сборки файлы
NanoMig, без изменений; полное дерево — в его репозитории на указанном commit.

`prepare.py` получал `fpga/` из `upstream/` до версии 0.11; правки 0.12–0.13.6 (видео 576p, кэш и снуп, блиттер, режим
совместимости) внесены прямо в `fpga/`, поэтому `prepare.py` теперь **не запускать** — он перезапишет их.

Слой ESP: `esp/tools/build.ps1`. Полный RTL-симулятор (весь верхний модуль, TG68K, контроллер SDRAM, видеотракт и
сериализатор) — в [`sim/`](sim/README.md); собственные тестовые ROM без Kickstart: `sim/diagnostic_rom.py`, `dma_rom.py`,
`cache_rom.py` (код в chip RAM при турбо и снупе кэша), `blit_rom.py` и `blitcheck_rom.py` (блиттер и захват видео при широком
оверскане). Выпуски собираются `build.py fpga --place-option 2`. Тесты — `tests/run*.py`; они требуют Verilator, Icarus Verilog
и MSVC, а пути к инструментам в них заданы под рабочий ПК автора. Модель загрузки (`tests/run_boot.py`)
не входит в комплект без вашего файла Kickstart в `ROM/`. `tests/run_ide_write.py` и `tests/run_ide_floppy.py` Kickstart не нужен: у них
своя короткая программа в ROM модели, а `run_ide_floppy.py` принимает образ дискеты параметром `--adf`.

Прямая запись на карту по сети: `tang_tool.py sd-put <IP ESP> AMIGA.BIN CORES/AMIGA.BIN`.
