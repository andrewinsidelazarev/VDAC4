# ZX Spectrum Next на VDAC4

Ядро — [NextNano](https://github.com/RetroSilicon/NextNano) (ZX Next для Tang Nano 20K), перенесённое на
плату VDAC4. Готовые файлы — [`../SD/CORES/NEXT.BIN`](../SD/CORES/NEXT.BIN) (0.37, VERSION `03010025`)
и [`NEXT.ELF`](../SD/CORES/NEXT.ELF) (0.7).

## Что здесь

| Папка | Что |
|---|---|
| [`fpga`](fpga) | исходники ядра: общий код ZX Next из NextNano и обвязка VDAC4 [`fpga/vdac4`](fpga/vdac4) |
| [`esp`](esp) | слой ESP `NEXT.ELF`: клавиатура, мышь и джойстик Evo, звук на ЦАП ESP, выбор частоты в `CORES/next.cfg`, выход в WC |
| [`rom-patch`](rom-patch) | правка ROM NextZXOS 2.09 для общего выбора частоты и её исходник |

## Чем отличается от NextNano

- **Верхний модуль платы VDAC4** (`fpga/vdac4/ZXNext_vdac4.sv`): выводы платы, LINK с ESP
  (`next_link.sv`: клавиши, мышь, звук, частота), запрос возврата в TS-Config через BL616, сброс от Evo.
- **Исправления общего кода** (подробности — [NextNano issue #13](https://github.com/RetroSilicon/NextNano/issues/13)):
  - сброс без остановки видеоделителя: процессор больше не теряет первое чтение после сброса;
  - DMA ждёт готовый байт банка 5;
  - программный выбор частоты в NR07;
  - место для Layer 2 в арбитре SDRAM.
- **Запись в банк 5 из регистров** (0.37, [NextNano issue #14](https://github.com/RetroSilicon/NextNano/issues/14)).
  - **Как было:** вход записи `bank5_ram` (экран, системные переменные и стек NextZXOS) был комбинационным. Сигналы считались от регистров по спаду за полтакта и переключались сразу после фронта записи.
  - **Чем кончалось:** Gowin собирает банк из 8 блоков BSRAM по одному биту. При одной раскладке отдельные блоки записывали неверные биты, при другой нет. Отсюда зависания после TBBlue, мусор на экране, отказ SD в NextZXOS и порча каталогов на карте.
  - **Что сделано:** теперь WE, адрес и байт запоминаются на фронте записи, и BRAM пишет их тактом позже.
  - **Проверено на плате:** 3,4 млн чтений процессора и 174 млн чтений ULA без единой ошибки.
- **Без сиреневой полосы слева** (0.37): в DVI без островов данных телевизор показывал защитную полосу
  видео точками. Вместо неё кодер шлёт управляющий символ CTL=00 (`video/hdmi/hdmi.vhd`).
- **Общий выбор частоты** (регистр F1): его меняют F8, стрелки меню и NMI, он переживает F4, а слой
  ESP хранит его в `CORES/next.cfg` между запусками. Нужна правка ROM из [`rom-patch`](rom-patch).
- **Мышь**: ось Y без лишней инверсии. **Звук**: правильные беззнаковые отсчёты и нормализация
  громкости на ESP.
- **Запас по времени**: в SDC стоит `set_max_delay 16.5` на пути данных в процессор и DMA и обратно,
  а также на строб чтения и записи DMA. Эти регистры защёлкиваются по спаду такта 28 МГц, полтакта —
  17,8 нс; предел держит раскладку подальше от края.

## Сборка

Ядро: Gowin EDA 1.9.11, в папке `fpga` выполнить `gw_sh nextVdac4.tcl`, результат —
`impl/pnr/nextVdac4.bin` (это и есть `NEXT.BIN`).

У 0.37 в отчёте `nextVdac4.tr`:
- Fmax `clk_28` — 30,1 МГц, `clk_140` — 130,5 МГц;
- два конца на −0,21 нс. Это нарушение искусственного предела 16,5 нс из SDC: настоящий бюджет полутакта 17,8 нс;
- худший настоящий запас полутакта — +0,15 нс (`BusAck` → `MReq_Inhibit`).

Любая правка ядра даёт новую раскладку, поэтому новую сборку надо проверять на плате.

Слой ESP: ESP-IDF 6.0, `esp/tools/build.ps1`. Слою нужна прошивка ESP с SDK модулей 1.9 (vdac4-0.1.99+).
