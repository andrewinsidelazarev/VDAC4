# BL616 модуля Tang Nano 20K

BL616 — второй микроконтроллер на Tang Nano 20K. На VDAC4 у него своя прошивка:

- **Сопроцессор FT812** — то, что в настоящем FT812 делает микропрограмма J1: кольцо RAM_CMD,
  виджеты, текст шрифтами ПЗУ, картинки CMD_LOADIMAGE (JPEG, в том числе прогрессивный, PNG всех
  видов; с прошивки 39 — и свои CMD_LOADIMAGE_BOX и CMD_IMAGEINFO, см. «Картинки»), CMD_INFLATE. Регистры,
  дисплей-лист и RAM_G — в ядре FT812 (слот 1 flash Tang), BL616 читает и пишет их по SPI.
- **Свои 3D-команды VDAC4** `0xFFFFFFA0…AF`: сетки из RAM_G, отсечение, свет, z-буфер, текстуры,
  туман; кадр уходит в RAM_G битмапом. Версия 3D API — 3 ([`docs/3d-api-v3.md`](docs/3d-api-v3.md),
  заголовок для программ [`copro/vdac3d.h`](copro/vdac3d.h)).
- **Видео FT812** (с прошивки 31): CMD_MEDIAFIFO, CMD_VIDEOSTART, CMD_VIDEOFRAME — MJPEG AVI из
  медиа-FIFO; CMD_LOADIMAGE с OPT_FULLSCREEN вписывает картинку в 1024×768 (с 30) — для FTVIEW.
- **Кэш ядер** для ядер с карты Tang (Next, NES): ESP кладёт ядро во flash BL616, BL616 грузит
  его в ПЛИС по JTAG, а по просьбе ядра (F12) возвращает TS-Config.
- **Перезагрузка ПЛИС** при переходе между слотами flash Tang (TS-Config ↔ FT812), с прошивки 35 —
  в любой слот (команда BOOT ящика: заголовок битстрима с адресом перехода по JTAG и Reconfig;
  ядро видео — слот 3).
- **Обновление по сети** через ESP — USB нужен только для первой установки.

Готовый образ — [`firmware/vdac4_copro_bl616.bin`](firmware/vdac4_copro_bl616.bin), прошивка **39**
(161904 байта, SHA-256 `25860afac13568a6a2a6932a714193854868067740edad3688a42667f635ab94`): картинки для
TSafari (см. «Картинки»). Проверена на ПК; на плате с 04.11.2026 (по сети, CP_INFO `C0270201`),
с TSafari ещё не проверялась. Прошлая — 38 (141568 байтов, SHA-256
`308dd94aa917b99c6987bd2cf78efce30e5684cac7bb48ed1138995fe825d3f9`).

В прошивке 38: сдвиг битстрима по JTAG в ITCM и прямой записью в регистры GPIO, такт около 5 МГц по расчёту. Ядро Amiga (907 КБ) выходит на LINK за 2,1 с, на прошивке 36 было 9,8 с. **Прошивку 37 ставить нельзя:** ядро из кэша грузится у неё около 25 с, а ESP ждёт 15 с и сообщает «no core answered on LINK after the load».

В прошивке 37: два ребра на строку вместо трёх в быстром пути (те же границы, сверено с полным перебором на 388 370 треугольниках), подготовка кадра и TEXMESH в ITCM, константы горячего кода без чтения из flash. Кадры в модели побитно те же, что у 36. На плате: ROOMTEST 33 кадра/с без SSAA и 11 с SSAA (на 36 было 30 и 10,7).

В прошивке 36: быстрый путь текстур работает и с SSAA, и с цветом без квантования; старые пути MESH и SSAA без программного
`double` (`(float)int64`); горячий код в ITCM; `pump` не ждёт места в очереди ПЛИС; чтение на 53,3 МГц, если самопроверка
проходит на обеих фазах (контрольной суммы у чтения нет). На плате: ROOMTEST с SSAA 7 → 10,7 кадра/с, без SSAA 27 → 30.
Она стоит на плате с 27.10.2026. ESP показывает версию в слове CP_INFO: `C023xxxx`. Что менялось
в 25–35 — в начале [`app/main.c`](app/main.c).

## Картинки (прошивка 39)

Задание `task_bl616_images.md` (04.11.2026): браузер TSafari отдаёт JPEG и PNG сопроцессору, и
больше половины картинок сайтов не вставало. Разбор — [`copro/ft_image.c`](copro/ft_image.c).

### Что разбирается

| Картинка | CMD_LOADIMAGE (как FT812) | Примечание |
|---|---|---|
| JPEG baseline и extended (SOF0, SOF1) | RGB565 (OPT_MONO — L8) | серый, 4:4:4, 4:2:2, 4:2:0, 4:4:0, RST, таблицы Хаффмана 0…3 |
| JPEG прогрессивный (SOF2) | RGB565 (OPT_MONO — L8) | полосы спектра, приближение, серии EOB, RST; бит в бит с libjpeg-turbo |
| PNG серый 1, 2, 4, 8, 16 бит | L8 | 1/2/4 бита растягиваются (·255, ·85, ·17), у 16 — старший байт |
| PNG палитра 1, 2, 4, 8 бит | PALETTED565, с tRNS — PALETTED4444 | индексы — по байту, палитра с ptr |
| PNG RGB 8, 16 бит | RGB565 | 16 бит — старший байт |
| PNG серый с альфой, RGBA 8, 16 бит | ARGB4 | |
| PNG «через строку» (Adam7) | как без Adam7 | |

- JPEG — точки бит в бит с Pillow (libjpeg-turbo, islow), и прогрессивный тоже: после всех
  развёрток — то же обратное ДКП и то же восстановление цветности, что у baseline.
- tRNS у серого и RGB в CMD_LOADIMAGE не учитывается — как у FT812 (замер bt8xxemu 04.11.2026:
  те же байты, что без tRNS). PNG 1/2/4 бита, 16 бит, Adam7 и прогрессивный JPEG FT812 не
  разбирает (ошибка) — у VDAC4 это расширение.
- Не разбирается (ошибка с причиной): JPEG с арифметическим кодированием, lossless и
  иерархический, 12 бит, CMYK/YCCK, последовательный JPEG по частям (развёртки не всех компонент).
- CMD_LOADIMAGE — до 2047 точек по стороне (BITMAP_SIZE); прогрессивный — только сколько влезает
  в память BL616 (см. «Память»), больше — ошибка «велика».

### CMD_LOADIMAGE_BOX — 0xFFFFFFB0

Параметры (слова), за ними — байты файла, как у CMD_LOADIMAGE (дополнены до кратного 4):

| слово | что |
|---|---|
| `ptr` | куда класть выход в RAM_G |
| `options` | OPT_NODL (2) — без листа; OPT_MONO (1) — JPEG в L8 |
| `box` | `max_w \| max_h << 16` — рамка: пропорции сохраняются, увеличения нет |
| `room` | байтов RAM_G с `ptr` под выход и черновик |

- Картинка влезает в рамку и её выход — в `room`: выход как у CMD_LOADIMAGE (палитра остаётся
  палитрой), только tRNS у серого и RGB учитывается — выход ARGB4.
- Иначе — уменьшение по площади (каждая точка источника входит в точки выхода с долей
  пересечения, прозрачность — в предумноженном виде, без тёмной каймы) до рамки, а если выход в
  `room` не влезает — меньше рамки. Выход: без прозрачности — RGB565 (серый — L8), с прозрачностью
  (альфа, tRNS любого вида) — ARGB4. JPEG сначала уменьшается ДКП (1/2, 1/4, 1/8 — как
  `Image.draft`), потом по площади.
- Источник — до 65535 по стороне, выход — до 2047.
- Лист — как у CMD_LOADIMAGE; CMD_GETPROPS — начало выхода (`ptr`) и его размер.
- Черновик (Adam7, копия прогрессивного JPEG) — в RAM_G сразу за выходом, в пределах `room`.
- OPT_FULLSCREEN (VDAC4, вписать в холст 1024×768): если ядро фильтра Pillow не помещается
  (уменьшение больше 4 раз), — тем же уменьшением по площади на холст (раньше — ошибка). Так
  FTVIEW4 показывает и большие JPEG, и прогрессивные.

### CMD_IMAGEINFO — 0xFFFFFFB1

Четыре выходных слова о последней разобранной картинке (CMD_LOADIMAGE или CMD_LOADIMAGE_BOX):

| слово | что |
|---|---|
| 1 | размер источника `w \| h << 16` |
| 2 | размер выхода `w \| h << 16` |
| 3 | формат FT (биты 0…7), есть прозрачность (бит 8), шаг строки в байтах (биты 16…31) |
| 4 | байтов палитры с `ptr` (0 — нет; точки — с `ptr` + это число) |

### Причина ошибки

При ошибке картинки REG_CMD_READ = 0xFFF, как у FT812, а до сброса сопроцессора в RAM_CMD
(`0x308000`) лежит отчёт:

| байты | что |
|---|---|
| 0…3 | `'I' 'M' 'G'` и код: слово `0x00474D49 \| код << 24` |
| 4…7 | число к коду |
| 8… | строка ASCII с нулём на конце (до 120 байтов) |

| код | что | число | строка |
|---|---|---|---|
| 1 | повреждена | 1 — JPEG, 2 — PNG | `corrupt JPEG` |
| 2 | не поддерживается | что: 1 формат, 2 арифметика, 3 lossless, 4 12 бит, 5 компоненты, 6 вид PNG, 7 параметр, 8 развёртки | `unsupported: format` |
| 3 | велика для памяти | нужно байтов | `too big: need 5808360 bytes` |
| 4 | выход не влезает в `room` | нужно байтов | `no room: need 2 bytes` |
| 5 | размер больше предела | `w \| h << 16` | `too large: 4000x3000` |

### Память

Разбору отдаётся вся общая рабочая память сопроцессора (у 3D там треугольники, полосы, кэш
сеток) — 245 КБ, а JPEG ещё и место inflate (43 КБ): буферы берутся по размеру картинки.
`.bss` и куча — как у 38 (+168 байт `.bss`), код — +20 КБ. После картинки 3D перечитывает сетки и
ждёт новую текстуру, как и раньше (`ftc3d_scratch_lost`).

Прогрессивному JPEG нужны коэффициенты всей картинки (2 байта × 64 на блок, у 4:2:0 ~3 байта на
точку):

- **целиком** — если влезают в память BL616 (~150 КБ коэффициентов, примерно 320×240 у 4:2:0);
- **полосами** — иначе: файл копится (у рамки — в RAM_G за выходом, иначе — в памяти BL616),
  картинка выводится полосами строк MCU. На конце полосы у каждой развёртки ставится закладка
  (место в копии, буфер разрядов, серия EOB, предсказания DC), и следующая полоса берёт данные
  каждой развёртки прямо с неё — весь файл разбирается примерно один раз. Точки — те же, бит в
  бит. У рамки выход, если надо, — меньше рамки, чтобы рядом в `room` встала копия (оценка — 12
  байтов на блок, у сайтов — 8…9);
- **только DC** (ДКП 1/8) — у рамки и вписывания, если и полосами не выходит: картинка мельче,
  но целая.

Adam7: строки проходов — в памяти BL616 или (у рамки) в RAM_G, потом строки картинки собираются
кусками. Длинная работа без новых данных (конец прогрессивного, сборка Adam7) идёт кусками
(`FTC_IMG_BUSY`), между ними — главный цикл BL616.

## Установка

**Обновление по сети** — Evo включена, USB не нужен (`tang_tool.py` — в
[`ESP32 S3 Zero N8R8/Firmware/tools`](../../ESP32%20S3%20Zero%20N8R8/Firmware/tools)):

```
python tang_tool.py bl616 <IP ESP> vdac4_copro_bl616.bin
```

ESP проверяет SHA-256 и передаёт образ BL616 через ядро Tang. BL616 собирает его в памяти,
проверяет ещё раз, пишет во flash и перезапускается; `tang_tool` печатает новую версию.

**Первая установка по USB** — только на столе: Evo выключена, USB и Evo вместе не включать.
Образ ставится с адреса 0x40000 на место FPGA Companion; FPGA Partner Sipeed с 0x0 (USB-JTAG для
прошивки ПЛИС) остаётся. Tang подключить по USB с нажатой кнопкой UPDATE — BL616 появится как
«Bouffalo CDC DEMO» (COM-порт), затем в папке `firmware`:

```
BLFlashCommand.exe --interface=uart --baudrate=2000000 --port=COMn --chipname=bl616 --cpu_id= --config=flash_vdac4_copro.ini
```

`BLFlashCommand.exe` — из bouffalo_sdk (`tools/bflb_tools/bouffalo_flash_cube`). После записи
переподключить USB без кнопки. USB-клавиатура NextNano через FPGA Companion после этого не
работает: на VDAC4 клавиатура идёт от Evo через ESP.

## Сборка

Нужны bouffalo_sdk, компилятор T-Head (Xuantie GCC), make, ninja, cmake, python3:

```sh
export BL_SDK_BASE=<путь к bouffalo_sdk>
export PATH=<xuantie-gcc>/bin:$BL_SDK_BASE/tools/make:$BL_SDK_BASE/tools/ninja:$BL_SDK_BASE/tools/cmake/bin:$PATH
sh app/build.sh                 # → app/out/vdac4_copro_bl616.bin
```

bouffalo_sdk не собирает проект из пути с пробелами, поэтому `build.sh` копирует исходники в
каталог `WORK` (по умолчанию — во временный) и собирает там.

Проверки на ПК: `sh copro/test/run.sh` (нужны bt8xxemu и образ ПЗУ FT812 в `FT812_ROM_DIR`),
`sh app/test/run.sh`, `sh app/test/run_cache.sh`, `sh app/test/run_update.sh` (вместе с кодом
ESP из [`ESP32 S3 Zero N8R8/Firmware`](../../ESP32%20S3%20Zero%20N8R8/Firmware)).
