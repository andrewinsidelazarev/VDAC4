# 3D-команды VDAC4, версия 3

Свои команды сопроцессора FT812 на VDAC4: 16 кодов `0xFFFFFFA0…0xFFFFFFAF`. Программа кладёт их в
кольцо RAM_CMD, как обычные команды FT812, а исполняет их BL616 модуля Tang. Он считает сцену
целиком: матрицы, отсечение, свет, текстуры, растеризацию с z-буфером. Готовый кадр BL616 пишет
в RAM_G битмапом, и программа показывает его обычным `BITMAPS` в своём дисплей-листе.

Почему кадр считает BL616, а не растеризатор Tang: растеризатор выполняет дисплей-лист заново на
каждой строке и косых краёв не рисует. Сотня треугольников в листе заняла бы почти всё время
строки ещё до точек, а готовый битмап для растеризатора — одна фигура.

Коды объявлены в [`../copro/vdac3d.h`](../copro/vdac3d.h), исполняет их
[`../copro/ft_3d.c`](../copro/ft_3d.c). Сопроцессор ничего не знает о программах: координаты,
свет вершин и художественные настройки задаёт сама программа.

## Есть ли 3D

У настоящего FT812 этих команд нет, на них он даёт ошибку сопроцессора. Программа шлёт
`CMD_3D_INFO`: при ошибке (`REG_CMD_READ = 0xFFF`) сбрасывает сопроцессор через `REG_CPURESET` и
работает без 3D. При успехе первое слово ответа — `0x3D000000 | версия << 16 | лимит треугольников`:

| Версия | `CMD_3D_INFO` | Что добавилось | Прошивка BL616 |
|---|---|---|---|
| 1 | `0x3D010400` | команды A0…AC, 1024 треугольника | с 3 |
| 2 | `0x3D020400` | сглаживание SSAA 2×2 (`CMD_3D_TARGET`, формат `\| 0x100`) | до 16 включительно |
| 3 | `0x3D030500` | текстуры, туман, порог alpha (AD, AE, AF), 1280 треугольников | с 17, на плате — 24 |

## Общие правила

- Параметры — 32-битные слова кольца, little endian.
- **16.16** — число с фиксированной точкой: `0x00010000` = 1,0.
- **Угол** — доля оборота в 1/65536, как у `CMD_ROTATE` FT812: `0x4000` — 90°.
- Адреса RAM_G кратны 4. Чтение и запись проверяются на попадание в `[0, 0x300000)`.
- Ошибка в параметрах даёт `FTC_FAULT_3D`, как любая ошибка сопроцессора: `REG_CMD_READ = 0xFFF`.
- Камера стоит в начале координат: x вправо, y вверх, z от зрителя.
- Лицевая сторона грани — обход вершин против часовой стрелки, если смотреть на неё снаружи.

| Предел | Значение |
|---|---|
| треугольников в кадре, после отсечения | 1280 (лишние отбрасываются) |
| вершин в одной сетке | 512 |
| граней в одной сетке | 1024 |
| глубина стека матриц | 8 |
| кэш неизменных сеток (флаг 8 у `MESH`) | 6144 слова, до 16 сеток |
| текстура | 16384 байта, сторона 1…4095 |
| цель | ширина 4…1024 кратно 4, высота 1…2048 |

## Команды

| Код | Команда | Что делает |
|---|---|---|
| A0 | `CMD_3D_TARGET(addr, format, w \| h << 16)` | цель кадра в RAM_G |
| A1 | `CMD_3D_PROJECT(focal, znear)` | перспектива |
| A2 | `CMD_3D_IDENTITY` | единичная матрица модель-вид |
| A3 | `CMD_3D_TRANSLATE(x, y, z)` | сдвиг |
| A4 | `CMD_3D_ROTATE(ax, ay, az)` | поворот |
| A5 | `CMD_3D_SCALE(sx, sy, sz)` | масштаб |
| A6 | `CMD_3D_PUSH` | сохранить матрицу в стек |
| A7 | `CMD_3D_POP` | вернуть матрицу из стека |
| A8 | `CMD_3D_LIGHT(x \| y << 16, z \| ambient << 16 \| diffuse << 24)` | свет для `MESH` |
| A9 | `CMD_3D_CLEAR(argb)` | начать кадр, цвет фона |
| AA | `CMD_3D_MESH(vaddr, faddr, nv \| nf << 16, flags)` | одноцветная сетка в кадр |
| AB | `CMD_3D_RENDER` | нарисовать кадр в цель |
| AC | `CMD_3D_INFO(out info, out stats)` | версия, лимит, статистика прошлого кадра |
| AD | `CMD_3D_TEXTURE(addr, w \| h << 16, format, palette)` | загрузить текстуру |
| AE | `CMD_3D_TEXMESH(vaddr, faddr, nv \| nf << 16, flags)` | текстурированная сетка в кадр |
| AF | `CMD_3D_MATERIAL(fog_near, fog_far, fog_rgb, color_steps, flags)` | туман, квантование, порог alpha |

### A0 `CMD_3D_TARGET(addr, format, w | h << 16)`

Куда рисовать кадр. `addr` — адрес в RAM_G, кратный 4, и вся цель должна уместиться ниже
`0x300000`. Команда очищает список треугольников. Центр проекции — середина цели.

| `format` | Формат FT812 | Байтов на точку |
|---|---|---|
| 0 | ARGB1555 (фон — с альфой из `CMD_3D_CLEAR`) | 2 |
| 3 | L8 | 1 |
| 4 | RGB332 | 1 |
| 5 | ARGB2 (с упорядоченным дизерингом) | 1 |
| 7 | RGB565 | 2 |

`format | 0x100` — сглаживание SSAA 2×2 (с версии 2): четыре отсчёта на точку по повёрнутой сетке,
у каждого свои z и цвет, в цель идёт среднее. Цель и объём записи те же, счёт растёт вчетверо.

### A1 `CMD_3D_PROJECT(focal, znear)`

Оба параметра — 16.16, больше нуля. Точка `(x, y, z)` камеры уходит на экран в
`x' = w/2 + focal·x/z`, `y' = h/2 − focal·y/z`. Видно то, что дальше `znear`; треугольники,
пересекающие эту плоскость, обрезаются.

### A2…A7 — матрица модель-вид

Как в OpenGL: каждая команда умножает текущую матрицу справа, поэтому последняя команда
действует на вершины первой.

- `IDENTITY` — единичная матрица.
- `TRANSLATE(x, y, z)` — сдвиг, 16.16.
- `ROTATE(ax, ay, az)` — повороты в долях оборота: вокруг X, затем Y, затем Z
  (`M = M·Rz·Ry·Rx`). Положительный угол поворачивает X к Y, Y к Z, Z к X.
- `SCALE(sx, sy, sz)` — масштаб, 16.16.
- `PUSH` / `POP` — стек на 8 матриц. `PUSH` в полный стек и `POP` из пустого ничего не делают.

Матрица действует на `MESH` и `TEXMESH` в момент их исполнения.

### A8 `CMD_3D_LIGHT(x | y << 16, z | ambient << 16 | diffuse << 24)`

Направленный свет для `MESH`. `x`, `y`, `z` — направление на источник в пространстве камеры,
int16, любой длины. `ambient` — фоновый свет, `diffuse` — рассеянный, оба 0…255. На `TEXMESH` не
действует: там цвет вершин считает программа.

### A9 `CMD_3D_CLEAR(argb)`

Начать новый кадр: список треугольников пуст, фон — `argb` (0xAARRGGBB). Альфа фона нужна для
ARGB1555 и ARGB2.

### AA `CMD_3D_MESH(vaddr, faddr, nv | nf << 16, flags)`

Одноцветная сетка из RAM_G в список кадра.

- Вершина — 8 байтов: `int16 x, y, z, 0`, целые единицы модели.
- Грань — 8 байтов: `uint16 a, b, c` (индексы вершин) и цвет RGB565.
- Грань с индексом за `nv` пропускается.

| Бит `flags` | Что |
|---|---|
| 0 (1) | отбросить нелицевые грани |
| 1 (2) | свет по граням (`CMD_3D_LIGHT`) |
| 2 (4) | гладкий свет по Гуро: нормали вершин — из граней вокруг; бит 1 тогда не нужен |
| 3 (8) | сетка не меняется: BL616 читает её из RAM_G один раз и держит копию до сброса сопроцессора |

Без битов 1 и 2 грани рисуются своим цветом без света. Без бита 3 сетка читается заново при
каждой команде, а её прежняя копия выбрасывается.

### AB `CMD_3D_RENDER`

Нарисовать накопленный кадр в цель. Кадр считается полосами, каждая полоса сразу уходит в RAM_G.
Команда завершается, когда записана вся цель: `REG_CMD_READ` продвигается только после последней
полосы. Поэтому следующие команды кольца уже видят готовый кадр.

### AC `CMD_3D_INFO(out info, out stats)`

Как `CMD_GETPROPS`: ответ записывается на место параметров в кольце.

- `info` = `0x3D000000 | версия << 16 | лимит треугольников`; в версии 3 — `0x3D030500`.
- `stats` = треугольников прошлого кадра `| мс << 16`. Время — счёт `CMD_3D_RENDER` на BL616; если
  оно больше 65 535 мс, старшие 16 битов — `0xFFFF`.

### AD `CMD_3D_TEXTURE(addr, w | h << 16, format, palette)` — версия 3

Загружает текстуру (атлас) из RAM_G в память BL616. Выборка — по ближайшему текселю, за краем
координата зажимается. Сторона — 1…4095, объём — до 16384 байтов. Последнее чтение округляется
до 4 байтов, поэтому за текстурой в RAM_G нужен хвост до кратного 4.

| `format` | Тексель | `palette` |
|---|---|---|
| 0 | индекс uint8 | 256 слов ARGB8888 |
| 1 | RGB565 | не нужна |
| 2 | ARGB1555 | не нужна |
| 3 | индекс uint8 | 256 пар `{ARGB8888, flags}` |

Флаги палитры формата 3: бит 0 UNLIT — не умножать на RGB вершин, бит 1 NO_FOG — не смешивать с
туманом. Так помечают лампы, индикаторы, интерфейс и другие светящиеся детали.

- В кадре одна текстура. Менять её можно только при пустом списке треугольников: после `CLEAR`
  или `TARGET`, до первой сетки.
- Источник читается при каждом вызове. Если программа изменила текстуру в RAM_G, нужно вызвать
  `TEXTURE` снова.
- `CMD_LOADIMAGE`, `CMD_INFLATE` и обновление прошивки BL616 занимают ту же память. После них
  тоже нужно вызвать `TEXTURE` заново, иначе `TEXMESH` вернёт ошибку.

### AE `CMD_3D_TEXMESH(vaddr, faddr, nv | nf << 16, flags)` — версия 3

Текстурированная сетка в список кадра. Она может стоять в одном кадре с `MESH`, z-буфер у них
общий. До 512 вершин и 1024 граней.

Вершина — 16 байтов (`vdac3d_vertex`):

| Поле | Формат | Значение |
|---|---|---|
| `x, y, z` | int16, Q8.8 | координаты модели, −128…127,996 |
| `u, v` | uint16, Q12.4 | координаты в текселях, а не доли размера |
| `r, g, b` | uint16, Q4.12 | множители цвета 0…15,9998; 4096 = 1,0 |

Грань — 8 байтов: `uint16 a, b, c` и 0. Индекс за `nv` или ненулевое последнее поле — ошибка.
`flags` — только бит 0, отбросить нелицевые грани.

- Действуют матрицы A2…A7 и `PROJECT`. `LIGHT` не действует: свет вершин программа считает сама и
  передаёт готовым RGB.
- UV и RGB интерполируются с поправкой на перспективу; при отсечении интерполируются все атрибуты.
- Прозрачный тексель отбрасывается до записи глубины. SSAA работает, как у `MESH`.
- Пока `TEXMESH` не исполнена, её вершины и грани в RAM_G менять нельзя.

### AF `CMD_3D_MATERIAL(fog_near, fog_far, fog_rgb, color_steps, flags)` — версия 3

Задаётся при пустом списке треугольников и действует на все `TEXMESH` до следующей смены или сброса
сопроцессора. На `MESH` не действует.

| Параметр | Значение |
|---|---|
| `fog_near`, `fog_far` | 16.16, глубина в пространстве камеры; при включённом тумане 0 ≤ near < far |
| `fog_rgb` | цвет тумана, `0xRRGGBB` |
| `color_steps` | 16.16 ≥ 0; 0 — без квантования, иначе канал = `floor(канал · steps) / steps` |
| `flags`, бит 0 | туман |
| `flags`, бит 1 | туман по smoothstep вместо линейного |
| `flags`, биты 8…15 | порог alpha 0…255: тексель с alpha меньше порога отбрасывается |

Порядок: RGB вершин (кроме UNLIT), туман (кроме NO_FOG), квантование, перевод в формат цели.
После сброса сопроцессора тумана и квантования нет, порог alpha — 128.

Полупрозрачного смешивания, mipmap, билинейной выборки и нескольких текстур в одном кадре пока
нет. Тексель, прошедший порог alpha, записывается непрозрачным.

## Кадр

Один раз: `CMD_3D_TARGET`, `CMD_3D_PROJECT`, `CMD_3D_LIGHT`. На каждом кадре:

1. `CMD_3D_CLEAR`;
2. при текстурах — `CMD_3D_TEXTURE` и `CMD_3D_MATERIAL`;
3. для каждого объекта — `IDENTITY` или `PUSH`, `TRANSLATE`, `ROTATE`…, затем `MESH` или `TEXMESH`,
   `POP`;
4. `CMD_3D_RENDER`;
5. свой дисплей-лист: `CMD_DLSTART`, `CMD_SETBITMAP(цель, формат, w, h)`, при увеличении —
   `CMD_LOADIDENTITY`, `CMD_SCALE`, `CMD_SETMATRIX` и `BITMAP_SIZE`, затем `BEGIN(BITMAPS)`,
   `VERTEX2F`, `DISPLAY`, `CMD_SWAP`.

Растеризатор Tang читает RAM_G на каждом кадре, поэтому цель, в которую сейчас пишет BL616,
показывать нельзя. Цели нужны две через кадр, а лучше три по кругу: при ожидающем `CMD_SWAP`
BL616 уже считает следующий кадр.

## Растеризация

- Точки — по центрам, правило «верх-лево»: общий край двух треугольников закрашивается ровно
  один раз.
- Глубина — `znear/z` по плоскости треугольника, z-буфер 24 бита, ближе — больше.
- Свет Гуро интерполируется линейно по экрану.
- Кадр, где все треугольники текстурированы, сортируется от ближних к дальним; смешанный кадр
  рисуется в порядке подачи. В каждой точке побеждает ближний треугольник, при равной глубине —
  поданный раньше.

## Скорость

Предел — канал SPI от BL616 к ПЛИС, а не счёт. Кадр 256×192 занимает ~15 мс по байту на точку и
~30 мс по два байта. Запись полосы идёт через DMA, пока BL616 считает следующую.

На плате:
- DEMO3D (гладкий тор и шесть кубов, ~400 треугольников) — кадр BL616 38–41 мс;
- UNDERRUN (до ~950 треугольников с текстурами и туманом) на прошивке 22 — 8,56 кадра/с, из
  них `CMD_3D_RENDER` — 80 мс из 117 мс кадра.

## Проверки

`sh copro/test/run.sh` проверяет 3D версий 1 и 2 на ПК:
- сетки без щелей и наложений;
- сцена во всех пяти форматах при разной высоте полос;
- отбрасывание нелицевых граней, глубину и отсечение за камерой;
- ошибки параметров и `CMD_3D_INFO`.

Команды версии 3 и ускорения прошивок 19…24 проверялись в проекте UNDERRUN:
- синтетические текстуры через открытый ABI;
- 420 кадров побайтно против рендерера прошивки 19;
- запись полос через модель SPI и очереди ПЛИС.
