# VDAC4: универсальное расширение 3D API, версия 3

Это собственные команды VDAC4, исполняемые BL616 через RAM_CMD. Физический FT812 их не поддерживает. FPGA получает обычный итоговый bitmap в RAM_G. Коды A0–AC и их прежние форматы сохранены. CMD_3D_INFO сообщает версию 3 и ёмкость 1280 треугольников после отсечения.

Заголовок для приложений: `copro/vdac3d.h`. Сопроцессор не знает названий игр, объектов, размеров тайлов, формул игровых источников света или «особых» RGB-цветов. Координаты, свет и художественные настройки формирует приложение.

Все параметры — 32-битные слова little endian. Адреса RAM_G кратны 4. Чтения полностью проверяются на попадание в диапазон `[0, 0x300000)`. Ошибка команды даёт FTC_FAULT_3D и REG_CMD_READ=0xFFF.

## CMD_3D_TEXTURE — 0xFFFFFFAD

`CMD_3D_TEXTURE(tex_addr, width | height << 16, format, palette_addr)`

Загружает текстуру из RAM_G в локальный кэш BL616. Фильтрация — nearest; координаты за краем зажимаются (clamp-to-edge). Размеры 1…4095, произведение размеров и байтов на тексель не больше 16384. Последнее чтение округляется до 4 байт: источник должен иметь это выравнивание и хвост.

| Format | Тексель | Палитра |
|---|---|---|
| 0, INDEX8_ARGB8888 | индекс uint8 | 256 слов ARGB8888 |
| 1, RGB565 | uint16 RGB565 | не используется |
| 2, ARGB1555 | uint16 ARGB1555 | не используется |
| 3, INDEX8_MATERIAL | индекс uint8 | 256 пар `{ARGB8888, flags}` |

Флаги элемента расширенной палитры: bit 0 UNLIT — не умножать этот материал на RGB вершин; bit 1 NO_FOG — не смешивать с цветом тумана. Прочие биты зарезервированы. Это свойства материала для, например, индикаторов, ламп, интерфейса и светящихся деталей. Они не вычисляются из цвета внутри BL616.

Одна активная текстура/атлас на накопленный кадр. Менять её можно только при пустом списке треугольников — после CLEAR или TARGET, до MESH/TEXMESH. Вызов всегда перечитывает источник, поэтому изменение RAM_G само по себе кэш не обновляет. CMD_LOADIMAGE, CMD_INFLATE и обновление прошивки используют общую рабочую память: после них необходимо снова вызвать TEXTURE. TEXMESH с недействительным кэшем возвращает ошибку.

## CMD_3D_TEXMESH — 0xFFFFFFAE

`CMD_3D_TEXMESH(vertex_addr, face_addr, nv | nf << 16, flags)`

Добавляет сетку в общий список кадра. Она может сосуществовать с прежними одноцветными MESH; у всех общий z-буфер. Предел одной сетки: 512 вершин, 1024 грани. Индексы за пределами `nv` и ненулевое резервное поле грани — ошибка. Флаг bit 0 включает прежнюю конвенцию отсечения нелицевых граней; прочие биты пока не принимаются.

Вершина — 16 байт, `vdac3d_vertex`:

| Поле | Формат | Значение |
|---|---|---|
| x, y, z | int16, Q8.8 | координаты модели, −128…127.996 |
| u, v | uint16, Q12.4 | координаты в текселях, а не доли размера |
| r, g, b | uint16, Q4.12 | линейные множители цвета, 0…15.9998; 4096 = 1 |

Грань — 8 байт: `{uint16 a, b, c, reserved=0}`. Действуют существующие IDENTITY, TRANSLATE, ROTATE, SCALE, PUSH, POP и PROJECT. Большие миры можно передавать относительно камеры или использовать масштаб модели. Направленные/точечные источники, нормали и материалы сцены рассчитывает приложение; TEXMESH принимает готовый RGB вершин.

UV и RGB интерполируются с поправкой на перспективу через `attribute/z`. Отсечение по ближней плоскости и защитным боковым плоскостям интерполирует все атрибуты. Прозрачный тексель отбрасывается **до записи глубины**. Поддерживается прежнее SSAA 2×2.

## CMD_3D_MATERIAL — 0xFFFFFFAF

`CMD_3D_MATERIAL(fog_near, fog_far, fog_rgb, color_steps, flags)`

Параметры задаются при пустом списке треугольников, действуют на все TEXMESH до изменения/сброса; на прежние MESH не влияют.

| Параметр | Значение |
|---|---|
| fog_near, fog_far | signed 16.16, глубина в пространстве камеры; при включении тумана 0 ≤ near < far |
| fog_rgb | младшие 24 бита RRGGBB; цвет тумана |
| color_steps | неотрицательное 16.16; 0 отключает квантование, иначе `floor(channel * steps) / steps` |
| flags bit 0 | включить туман |
| flags bit 1 | smoothstep вместо линейного тумана |
| flags bits 8…15 | alpha reference, 0…255: отбросить тексель с alpha < reference |

Сначала применяется RGB вершин (кроме UNLIT), затем туман (кроме NO_FOG), затем необязательное квантование и перевод в формат цели. Значения RGB больше единицы допустимы до последнего преобразования. Сброс: туман/квантование выключены, alpha reference=128.

Это alpha test для непрозрачных поверхностей и вырезанных спрайтов. Полупрозрачное смешивание, mipmaps, билинейная фильтрация текстуры и несколько одновременно активных атласов в этой версии не реализованы. Данные, прошедшие alpha test, записываются как непрозрачные.

## Порядок кадра

1. TARGET, PROJECT; CLEAR.
2. При необходимости TEXTURE и MATERIAL.
3. Преобразования и любое число MESH/TEXMESH в пределах общего лимита.
4. RENDER; обычный FT display list показывает bitmap цели.

Нельзя показывать цель в момент записи. Для цепочки с ожидающим CMD_SWAP используется три framebuffer. Данные динамической сетки нельзя перезаписывать, пока её TEXMESH не исполнена. При превышении ёмкости треугольники отбрасываются, как в v2; приложение должно соблюдать лимит, полученный через INFO.

## Проверки

`test/texture_test.c` использует только синтетические текстуры и публичный ABI. Проверяются перспектива, ориентация UV, совместная глубина старых и новых сеток, alpha test, цвет/диапазон тумана, SSAA, три прямых/палитровых формата, флаги материала, обновление кэша, отсечение и границы памяти. `copro/test/host_test.c` — прежний набор регрессий VDAC4.

Прошивки 20–21 ускоряют исполнение без изменения ABI: точное пошаговое вычисление пересечений рёбер вместо 64-битного деления на каждой строке, таблица byte/255, отдельный случай чёрного тумана, прямое формирование RGB565 и скалярный цикл атрибутов пикселя. Координаты, перспектива, освещение, квантование, alpha test и разрешение сохраняются. Общая таблица byte/255 занимает 1024 байта на контекст сопроцессора.

`test/render_equivalence.c` сравнивает 270 кадров игры и 150 синтетических сцен с рендерером прошивки 19 (`test/reference/ft_3d_v19.c`), включая SSAA, все форматы цели, цветной туман, прозрачность и большие рёбра за экраном. Это проверка конкретного набора кадров; прежние синтетические проверки ABI также остаются обязательными.

Прошивка 22 добавляет отсечение целиком скрытых отрезков строки до интерполяции UV/RGB. Верхняя граница глубины учитывает погрешность повторных сложений float; отбрасывание требует строго большей глубины во всех уже записанных отсчётах. Это сохраняет alpha test, прозрачные отверстия и порядок при равной 24-битной глубине, в том числе с SSAA.

Внутри одной TEXMESH преобразования и проекции общих вершин переиспользуются. Кэш размещается в прежней рабочей памяти и сбрасывается на каждой команде, поэтому динамические данные и изменения матрицы учитываются. Сначала проверяются индексы граней, затем из RAM_G читается только диапазон от минимального до максимального используемого индекса. Весь объявленный диапазон исходных данных по-прежнему проверяется на границы RAM_G. При пустом списке граней вершины не читаются.

В прошивках 22 и 24 транспорт полос использует текущую свободную ёмкость очереди ПЛИС: до 511 слов данных и одно событие адреса в очереди на 512 событий. Проверочная прошивка 23 возвращала пакеты по 256 слов с резервированием места для всего пакета, однако пользователь подтвердил сохранение периодических полос. По его просьбе в 24 быстрый транспорт восстановлен; причина полос пока не установлена. READ_REQ сохраняет предел 256 слов, соответствующий его 8-битному полю. Подтверждение завершения RENDER по-прежнему выдаётся после записи всех полос. Вычислительные оптимизации 22 сохранены.

`test/visibility_test.c` проверяет границу глубины на 16 404 096 повторных сложениях, прозрачность, равную глубину и кэш общих вершин. `test/link_3d_test.c` пропускает реальные полосы RGB565/SSAA через исходную модель SPI и очереди ПЛИС: все 115 200 байт кадра должны быть записаны до CMD_READ, без переполнения. `test/link.ps1` также запускает прежние регрессии транспорта с медленной и быстрой очередью.
