# tracker

Проигрыватель трекерной музыки для звукового приложения VDAC4: модули XM, MOD
и S3M приводятся к одному контексту `xm_context_t`, звук отдаёт `xm_render`
(стерео, float).

Происхождение:

- ядро XM — libxm Ромена Дальмазо (Romain «Artefact2» Dalmaso), лицензия WTFPL
  (текст — в заголовке `include/tracker.h`);
- загрузчики MOD и S3M, раскладка памяти по группам и сглаживание —
  прошивка TS-Labs для ZX Evolution, `pentevo/esp32/src/main/tracker.cpp`
  (копия в `zx-evo-esp32-netdisk-r140g-more-name`, ревизия r140g).

Взята только библиотечная часть, до раздела «ESP32 tracker task / CLI / stream
integration»: задача проигрывания, консольные команды и потоковая загрузка
TS-Labs сюда не входят. Каналы AdLib модулей S3M молчат: эмулятора OPL в
прошивке VDAC4 нет (`opl_stub.h`).

Исправления VDAC4 в загрузчике XM (`tracker.cpp`, помечены `VDAC4:`; проверка —
`tests/test_tracker_files_host.py`):

- отсчёты лежат в одной группе памяти подряд, и 16-битный после 8-битного
  нечётной длины начинался с нечётного адреса. На x86 это проходит, а ESP32-S3
  на записи `data16[k]` падает (LoadStoreAlignment) — XM вешал прошивку.
  Теперь каждый отсчёт — с адреса, кратного 4;
- после 16-битного отсчёта нечётной длины в байтах (FT2 такие пишет) разбор
  сдвигался на байт, и модуль отвергался. Теперь позиция идёт по длине из
  заголовка отсчёта.
- узоры, на которые ссылается таблица порядка, но которых нет в файле, — как
  у FT2 пустые на 64 строки (раньше такой модуль отвергался: 48 файлов из 3073
  в проверочной коллекции);
- данных узора больше, чем ячеек, — разбор узора кончается, а не пишет мимо;
- коды эффектов 34 и дальше в файле — расширения OpenMPT, а внутри трекера эти
  коды заняты командами S3M (34 — скорость, 35 — темп): Y теперь панбрелло,
  Z и `\` — макрос MIDI (фильтр), прочие — без эффекта. Раньше Zxx в 18 файлах
  коллекции меняли темп, а Y — скорость.

Эффекты (проверка — `tests/test_tracker_host.py`; эффекты FT2 есть все):

- E3y (глиссандо) у XM и MOD: тон-портаменто звучит ближайшими полутонами,
  период скользит как обычно (было только у S3M, S1x);
- X5y (OpenMPT) — форма волны панбрелло;
- Zxx — макросы MIDI по умолчанию IT и OpenMPT: Z00…Z7F — срез, Z80…Z8F —
  резонанс резонансного фильтра IT (двухполюсный, формулы Olivier Lapicque,
  как у libxmp). Канал с фильтром рисуется кусками по 128 кадров в свой буфер
  и через фильтр идёт в общий микс; срез 127 без резонанса — фильтра нет.
- S3M: сэмплы ADPCM ModPlug (pack=4: 16 байт таблицы разностей, по два
  отсчёта в байте) распаковываются на месте (раньше модуль отвергался);
  команда за Z — без эффекта, как у ST3 (раньше отвергался весь модуль). Все
  команды S3M A…Z обрабатываются; S0x и SFx не исполняет и сам ST3.
- Длительность MOD/XM/S3M — `xm_scan_song`: тики без звука до конца песни
  (частоты не считаются, петли EFy не переворачиваются), начала позиций
  таблицы порядка — для времени после перемотки; состояние проигрывателя
  потом возвращается.
