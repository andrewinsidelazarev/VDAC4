# Передача аудио и ресурсов через SPI DMA

VDAC4 0.1.42 публикует версию канала 2 в слове состояния SPI Slave HD
(байты 60–63: состояние, `D7`, версия, номер запуска). Media Player 1.10
использует новый режим только при версии >= 2 и признаке PUT_CAPABLE.
Старые запросы и ответы канала сохраняются.

## Запрос и DMA

В обычном управляющем запросе канала выставляется флаг `10h`. Его данные:

| Назначение | Управляющие байты |
|---|---|
| AUDIO_DATA | `31 LEN_L LEN_H` |
| MOD_PUT | `6A LEN_L LEN_H OFFSET_0 OFFSET_1 OFFSET_2 OFFSET_3` |

Длина — от 1 до 8192 байт полезных данных, смещение MOD_PUT — LE32.
Другие команды в этом режиме не принимаются. Сумма короткого управляющего
запроса остаётся прежней; по массиву данных XOR/CRC не вычисляется.

ESP проверяет размер DMA-буфера и место во входной очереди, затем отвечает
PUT_READY. Z80 одной операцией DMA передаёт `ceil(LEN / 512)` секторов,
закрывает запись WR_DONE и посылает запрос PUT_DONE. ESP проверяет число
принятых байтов, отбрасывает дополнение последнего сектора и отвечает PUT_OK.
Повтор управляющего запроса с тем же TID возвращает прежний ответ, без
повторной постановки данных в очередь.

Отсутствие PUT_READY означает временную неготовность: плагин повторяет
запрос с новым TID после кадровой паузы, до 100 попыток. Ошибка DMA или
истечение ожидания передаётся обычному обработчику ошибок плагина.

## Внутри ESP

SpiLinkCore помещает в очередь внутренний кадр
`A6 CMD LEN_L LEN_H [OFFSET_LE32] DATA...` без байта контрольной суммы.
Его длина включает смещение MOD_PUT: максимум 8192 байта для AUDIO_DATA
и 8196 для MOD_PUT. FrameParser выдаёт обычный PacketView, поэтому
обработчики PLAYER и ModuleApp не зависят от способа доставки.

Обычный кадр `5A CMD LEN_L LEN_H DATA... XOR` по-прежнему ограничен
1024 байтами. Исполняемые ELF доставляются этим проверяемым протоколом;
новый режим используется для всех локальных форматов аудио и ресурсов
SF2, ROM OPL4, MWK. Интернет-радио получает звуковой поток через Wi-Fi.

## Чтение карты и память Z80

WC LOAD512 читает до 16 секторов за вызов в `D000–EFFF` страницы 1 плагина.
Данные передаются DMA непосредственно оттуда. На старой прошивке те же
прочитанные 8 КиБ разбиваются на прежние порции до 1024 байт. Хвост после
ID3 или перемотки остаётся в прежнем секторном буфере страницы 0.
Плагин устанавливает 14 МГц через WC API 14 и восстанавливает исходный
режим при выходе. Исходники Wild Commander не меняются.
