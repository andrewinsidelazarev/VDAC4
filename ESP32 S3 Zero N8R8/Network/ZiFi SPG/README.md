# ZiFi SPG для VDAC4

`zifi.spg` — интернет-клиент для ZX Evolution с TS-Conf. Программа открывает
каталоги vtrd.in, zxart.ee, prods.tslabs.info, bbb.retroscene.org, pouet.net и
других сайтов, скачивает игры, демо и образы дисков на SD-карту, показывает
тексты и картинки, играет AY-музыку.

Это переработка программы **ZiFi** Hacker VBI
([HackerVBI/ZiFi](https://github.com/HackerVBI/ZiFi), [zifi.vtrd.in](http://zifi.vtrd.in))
под ESP32-S3 платы VDAC4 (ESP на SPI ZX Evolution) с прошивкой из этого
репозитория. Интерфейс, меню, списки сайтов, просмотр текстов и картинок,
проигрыватель музыки остались от оригинала. Ниже перечислено, что изменено.
Программа собирается только для платы VDAC4 (обмен с ESP по SPI); версия для
переходника ZiFi (UART) здесь не собирается.

Готовая программа: [`build/zifi.spg`](build/zifi.spg).

## Главное

- **Исправлен файловый драйвер.** Старый FAT-движок Wild Commander
  (`WDFCVBI2.COD`) заменён исправленным ядром FAT32 из
  [Wild Commander Improved](https://github.com/andrewinsidelazarev/Wild-Commander-Improved),
  выделенным в самостоятельный драйвер
  [FAT32-Driver-ZX-Evolution](https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution).
- **Файл появляется под своим именем только целиком.** Любая загрузка сначала
  пишется во временный `имя.$$$` и получает своё имя одной операцией драйвера
  (FILEX MOVE с заменой). Оборванная загрузка, ошибка записи или пропажа
  питания не оставляют недописанного файла под настоящим именем и не портят уже
  скачанный.
- **Время файла.** Сохранённый файл и созданные каталоги загрузок получают время
  создания, изменения и доступа по часам ZX Evolution, как файлы, созданные WC.
- **Имена по правилам драйвера.** Знаки, недопустимые в длинном имени,
  заменяются на `_`, имя не длиннее 48 знаков, расширение сохраняется.
- **Нет текстового мусора в консоли.** Заодно пропало зависание мыши на
  реальной плате.
- **Нет артефактов на краю экрана.** Убраны тонкая линия по курсору на границе
  окна консоли и зелёная полоска в правом бордюре у нижней панели.
- **Нет гонки DMA при очистке строки состояния** после загрузки и при её
  отмене: DMA из прерываний (анализатор музыки, спрайт мыши) её больше не
  перебивает.
- **Индикатор скачивания работает и показывает реальный прогресс, а не
  имитацию.** Полоса заполняется пропорционально скачанному: 100 ячеек на весь
  файл. Если сервер длину не назвал (списки сайтов, онлайн-распаковщик
  zifi.vtrd.in), 100 ячеек — это предел приёмника: 640 КБ, у музыки 32 КБ.
- **Ошибки показываются в окне.** Любой отказ загрузки или записи на SD
  открывает окно поверх списка: «Error 404 - page not found», причина сбоя
  связи от ESP, код драйвера FAT32. Окно закрывается любой клавишей или
  щелчком; в консоль ничего не пишется, поэтому строки ошибок не остаются
  поверх ссылок.
- **Вопрос при сбое онлайн-распаковщика.** Если распаковщик zifi.vtrd.in не
  справился с архивом `.zip`, программа спрашивает «Online unpacker is damaged.
  Save zip archive? (Y/N)» и по «Y» сохраняет исходный ZIP.
- **Каталог загрузок без NTP.** Если время по сети не получено, дата каталога
  берётся из часов RTC, а если и они неверны, каталог называется `2026-01-01`.
- **Работа с ESP32-S3**: двоичный протокол вместо AT-команд ESP8266,
  HTTPS, прокси для ретро-архивов, часы по NTP.
- **Плата VDAC4.** С ESP программа говорит по SPI ZX Evolution — по той же шине,
  что и SD-карта.

## Подробно

### Файловый драйвер

- Оригинал писал файлы FAT-движком Wild Commander (`WDFCVBI2.COD`, страница
  `#0F`). Теперь используется самостоятельный драйвер FAT32-Driver-ZX-Evolution
  (страницы `#0E` и `#0F`) — исправленное ядро FAT32 из Wild Commander
  Improved. Относительно ядра исходного Wild Commander в нём исправлено:
  - обе копии FAT обновляются согласованно, а на томе с одной активной FAT
    пишется именно она;
  - конец цепочки кластеров распознаётся верно, без перехода по
    несуществующим кластерам;
  - пустой файл создаётся без ошибочной цепочки кластеров;
  - длинное имя удаляется целиком, без записей-«призраков»;
  - короткие имена 8.3 получают правильные суффиксы `~1`…`~999`;
  - ошибка чтения или записи SD останавливает операцию, а не продолжает её с
    неверными данными;
  - дозапись (`APPEND`) заранее выделяет недостающую цепочку и публикует
    точный размер файла;
  - находится том внутри расширенного раздела (цепочка EBR): в исходном коде
    обход не доходил до логического тома;
  - недействительная подсказка FSInfo пропускается, свободное место ищется по
    FAT.
- Программа работает с драйвером через `fat32_adapter.asm` (чтение `zifi.ini`)
  и `fat32_window.asm` (каталоги загрузок, имя файла, временный файл, подмена и
  время файла). Встроена версия драйвера от 2026-10-07: проверки сохранности
  данных `safety.asm`, CRC16 и статус карты после каждой записи у SD-ZC,
  проверка геометрии тома, FILEX. Подробности — в [FAT32.md](FAT32.md) и в
  [README драйвера](https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution#readme).
  `WDFCVBI2.COD` в сборку больше не входит.

### Сохранение: временный файл и подмена

- Любая загрузка пишется во временный файл `имя.$$$` рядом с целью (например,
  `game.trd.$$$`). После полной записи и закрытия FILEX MOVE с заменой
  переводит запись цели на цепочку временного одним сектором каталога, затем
  удаляет запись временного и освобождает прежнюю цепочку цели. Цели не было —
  временный просто получает её имя.
- Поэтому под настоящим именем лежит либо прежний файл, либо новый целиком.
  Недописанный остаток виден как `имя.$$$` и удаляется при повторной загрузке
  того же файла.
- Цель — каталог с тем же именем или файл «только для чтения»: отказ до записи
  (`FAT32 code #1A` и `#18`).
- FAT32 не ведёт журнала. Если питание пропало ровно в окне подмены (запись
  цели уже смотрит на цепочку временного, а запись временного ещё не удалена),
  у них общая цепочка. Такой временный не удаляется — удаление освободило бы
  цепочку цели: повтор той же загрузки отвечает `FAT32 code #20`, том не
  меняется, файл под своим именем уже новый и целый. Чинит chkdsk.

### Время файла

- Сохранённый файл получает время создания (с сотыми долями нечётной
  секунды), изменения и доступа по часам ZX Evolution (CMOS); недостающие
  каталоги `zifi`, `downloads` и каталог даты — тоже. Время местное, как у WC;
  FTP-сервер прошивки переводит его в UTC по полю `time:` из `zifi.ini`.
- Часы читаются как у WC Improved: два снимка подряд должны совпасть, у каждого
  поля проверяются цифры BCD (или двоичный режим часов) и диапазон, у дня —
  длина месяца, год — 2026–2099. Понят и 12-часовой режим (полночь — 12 AM,
  бит 7 часов — PM): запись часов по NTP ставит 24-часовой, но при `time:none`
  режим остаётся прежним.
- Часы сбиты — дата каталога загрузок (от NTP, без него — часы или
  2026-01-01) и время 00:00; 31 апреля и подобное — 2026-01-01 00:00.

### Имя файла

- Имя — последняя часть пути запроса, как и раньше. Знаки, которых нет в
  длинном имени (управляющие, `" * / : < > ? \ |`, псевдографика CP866
  `#B0..#DF` и `#F2..#FF`, в том числе байты UTF-8 из ссылки), заменяются на
  `_`: прежде драйвер отвергал такое имя целиком.
- Точки и пробелы в конце срезаются. Пустое имя — `download`.
- Не длиннее 48 знаков: длиннее — укорачивается основа, расширение до восьми
  букв остаётся. Прежде длинный путь переписывал соседние переменные.
- Префикс `.ext` онлайн-распаковщика встаёт на место расширения, а у имени без
  точки дописывается (прежде разбор уходил за начало буфера).
- Окончание `.$$$` занято временными файлами: у скачанного имени точка перед ним
  заменяется на `_` (`demo.trd.$$$` → `demo.trd_$$$`). Иначе загрузка `demo.trd`
  приняла бы скачанный раньше `demo.trd.$$$` за свой остаток и удалила бы его.
  Посторонний файл `имя.$$$`, положенный в каталог загрузок другой программой,
  при загрузке `имя` будет удалён как остаток.
- Имя в формате 8.3 драйвер пишет без длинного имени, заглавными: `game.trd`
  на SD — `GAME.TRD`.

### Мусор в консоли и зависание мыши

- Прокрутка консоли запускала DMA, у которого страница источника и приёмника
  одна и та же (`Text_page`). Такая пересылка ненадёжна: в консоли появлялись
  случайные символы. Теперь прокрутка идёт командами `LDIR`/`LDDR` с теми же
  адресами и объёмом. После этого пропало и зависание мыши на реальной плате,
  которое лечилось только выключением питания.
- Текстовая страница очищается до включения растровых прерываний, поэтому при
  старте не мелькает старое содержимое памяти.

### Артефакты на краю экрана

- Тонкая линия по курсору на границе окна консоли. `PALSEL` менялся посреди
  кадра, а VGA-удвоитель строк берёт режим от предыдущей строки и палитру от
  текущей: граничная строка выводилась с палитрой графики. Теперь `PALSEL` и
  `TSCONFIG` выставляются один раз при старте.
- Зелёная полоска в правом бордюре у нижней панели. Цвет бордюра FPGA меняет
  сразу, а режим — только со следующей строки, поэтому правый край последней
  строки консоли выводился цветом текстовой палитры (`CRAM[#F4]`, зелёный).
  Теперь бордюр постоянный (`GFX_BORDER`), и его цвет меняется вместе с режимом
  ровно на границе строк.
- После просмотра картинки восстанавливается `PALSEL`.

### Мигание экранов после загрузки

- Экран делится растровыми прерываниями: `int_main` (строка 0), `int_text_cor`
  и `int_text_on` (84 и 88 — консоль в текстовом режиме), `int_text_ofcor` и
  `int_text_off` (284 и 287 — снова графика). Код страницы окон (`win_call`:
  имя файла, поиск, создание и подмена файла на SD, время файла) шёл под DI. На
  настоящей карте это долго: драйвер проверяет CRC каждого прочитанного сектора
  (около 2,9 мс на 14 МГц; Unreal отдаёт CRC `#FFFF`, и там проверка
  пропускается). TS-Config снимает запрос прерывания через 32 такта, пропущенное
  не повторяется — и после загрузки мигали оба экрана.
- Теперь `win_call` (`win_call_guarded`) прерываний не запрещает. На время вызова
  выключены обработчики интерфейса (`save_mode`) и музыка (`music_sw`: она меняет
  банки и умеет сама начать загрузку; под прежним DI она тоже стояла); прежние
  значения возвращаются. Вариант, где музыка здесь играла (на время вызова
  `fat_active`), на плате сломал загрузку — откачен; поэтому при записи на SD
  музыка коротко запинается. Порт `#27AF` не читается: опрос состояния DMA до запуска
  вешал программу на плате. Разбор — Codex.

### Музыка при загрузке картинки

- Пока шли приём, сохранение и подготовка показа, плеер то получал тики, то нет:
  на время кода страницы окон его останавливает `win_call_guarded` (прежде — DI),
  а AY при этом не глушился — висела нота, музыка рвалась и тормозила. Теперь при
  загрузке картинки с играющей музыкой она сразу останавливается и AY глушится
  (`music_player_mute`, позиция не теряется); музыка возобновляется, когда
  картинка на экране, или в главном цикле — после ошибки, неподдержанного файла
  или отмены (`pic_load`, `pic_resume`, `pic_wait`, `pic_shown`). Разбор — Codex.
- Обработчик просмотра картинки `int_gfx_view` сохраняет все регистры: плеер
  портит IY и альтернативные, а сохранялись только AF, HL, DE, BC и IX.

### Гонка DMA при очистке строки состояния

- После приёма файла и при отмене загрузки строка состояния очищается DMA
  (`status_copy`). Прежде это шло при работающих обработчиках интерфейса, а
  анализатор музыки (`int_text_off`) и спрайт мыши (`int_main`) пишут те же
  регистры DMA из прерывания и могли перебить список или саму пересылку.
  Теперь `status_clear` делает это так же, как копирование списка рядом:
  `off_int_dma`, пересылка, `on_int_dma`. Состояние DMA (`#27AF`) до запуска не
  опрашивается: сборка с таким опросом висла на плате сразу после загрузки.

### Индикатор скачивания

- В оригинале индикатор был полосой активности: ячейка сдвигалась на каждые
  256 принятых байтов и шла по кругу, независимо от размера файла. Сколько
  скачано, по нему понять было нельзя.
- После перехода на протокол ESP32-S3 индикатор перестал двигаться совсем: шаг
  брался из старшего байта длины порции, а порция протокола не больше 255
  байтов, так что шаг всегда был нулевым.
- Теперь индикатор показывает реальный прогресс. Длину файла сообщает ESP
  (`Content-Length`), и полоса заполняется пропорционально принятому: 100
  ячеек на весь файл. Замер на загрузке 640 КиБ: ровно 100 шагов из 100 и в
  эмуляторе, и на настоящей плате ([`tools/verify_progress_bar.py`](https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution/blob/main/tools/verify_progress_bar.py) в
  репозитории драйвера).
- Если сервер длину не назвал, реальный прогресс показать невозможно, и
  индикатор работает как полоса активности: ячейка на 256 байт.

### Окна ошибок

- Раньше об отказе загрузки сообщала только строка в консоли. Индикатор после
  отказа стирается, и ошибку было легко не заметить: на экране оставалась
  полоса, как будто загрузка ещё идёт.
- Теперь любой отказ открывает модальное окно поверх списка:
  - код HTTP с расшифровкой: «Error 404 - page not found», «Error 403 -
    forbidden», «Error 503 - service unavailable» и другие частые коды от 400
    до 504; прочие коды — «Error NNN - HTTP error»;
  - сбой связи: в первой строке — что не удалось («HTTP(S) request failed»,
    «NET_RECV failed»), во второй — причина от ESP, например
    `get:header timeout` или `recv:body timeout`;
  - длина не совпала с `Content-Length`, пустой ответ, файл `.zip` без
    сигнатуры ZIP, превышен буфер загрузки 640 КиБ;
  - ошибка записи на SD — с кодом драйвера («FAT32 code #NN»).
- Окно закрывается любой клавишей или щелчком мыши, область под ним
  восстанавливается. В консоль окно ничего не пишет: в режиме списка строка
  консоли легла бы поверх ссылок и осталась бы там серыми буквами.
- Код окон вынесен в отдельную страницу памяти (`#11`): в странице программы до
  границы `#BE00` оставалось всего 16 свободных байтов. Там остался только
  короткий переходник. В той же странице — разбор имени, подмена и время файла
  (`fat32_window.asm`); вызываются через `win_call`.

### Онлайн-распаковщик ZIP

- Как и в оригинале, ссылка на архив `.zip` скачивается через онлайн-распаковщик
  `zifi.vtrd.in/unzipremote.php`: он возвращает уже распакованный образ
  (`.trd`, `.scl` и т. п.).
- Если распаковщик не ответил, вернул ошибку HTTP или прислал вместо файла
  что-то другое (например, страницу ошибки), окно ошибки не выводится, а
  программа спрашивает: «Online unpacker is damaged. Save zip archive? (Y/N)».
  «Y» — исходный ZIP скачивается напрямую с сайта и сохраняется как есть,
  «N» — ничего не сохраняется.
- Для ссылок не на `.zip` вопроса нет: при сбое выводится обычное окно ошибки.

### Связь с ESP

- Оригинал работал с модулем ESP8266 на стандартной AT-прошивке
  (`AT+CIPSTART`, `+IPD`, …); кроме того, была отдельная сборка для кабеля
  RS232. Теперь обмен идёт двоичным протоколом прошивки ESP32-S3: пакет
  `[#5A][CMD][LEN_L][LEN_H][DATA…][CSUM]` (`shared/z80/proto.asm`, `net.asm`).
  Канал — SPI (`shared/z80/zifi_spi.asm` через `zifi_link.asm`, ключ
  `ZIFI_SPI` задан в `zifi.asm`): ESP — ведомый SPI Slave HD, порты `#57`/`#77`
  общие с SD-картой; канал выбирает ESP на время своего обмена, драйвер FAT32 —
  карту на время своего. Команды оригинала сохранены для сверки в
  [ORIGINAL_AT_COMMANDS.md](ORIGINAL_AT_COMMANDS.md).
- ESP VDAC4 не отвечает — на экране «Error: VDAC4 ESP does not answer (SPI)».
- HTTP-запрос целиком выполняет ESP. Z80 получает код ответа HTTP,
  `Content-Length` и затем тело.
- Добавлен HTTPS: TLS, проверку сертификата и до пяти редиректов выполняет
  прошивка.
- `zifi.ini` при старте целиком уходит на ESP командой `WIFI_INI`. Прошивка
  подключается к Wi-Fi и возвращает адрес, выданный роутером; он выводится на
  экран.
- Удалены сборка для кабеля RS232 и самообновление с zifi.vtrd.in: там лежит
  оригинальная AT-версия, и её установка затёрла бы этот порт.

### Старт и диагностика

- При запуске программа проверяет, что прошивка ESP отвечает, выводит IP-адрес,
  сведения о прошивке и состояние прокси, затем делает пробный HTTP-запрос к
  zifi.vtrd.in. Причины сетевых ошибок (ESP не отвечает, сбой открытия или
  приёма, пустой ответ, тайм-аут) пишутся в консоль программы.

### Часы и каталог загрузок

- Оригинал брал дату с zifi.vtrd.in вместе с проверкой обновлений. Теперь время
  приходит по NTP через ESP; смещение часового пояса задаёт поле `time:` в
  `zifi.ini`, а `time:none` оставляет часы компьютера нетронутыми.
- Файлы по-прежнему сохраняются в `zifi/downloads/<дата>`, но каталог даты
  называется `ГГГГ-ММ-ДД` вместо `ДД_ММ_ГГГГ`: сортировка по имени совпадает с
  сортировкой по дате.
- Если NTP не ответил, дата каталога берётся из часов RTC ZX Evolution, когда
  она правдоподобна (год 2026–2099, месяц 1–12, день 1–31); иначе каталог
  называется `2026-01-01`. На старте в консоли видно, откуда взята дата.

### Прокси для ретро-архивов

- Для vtrd.in, zxart.ee и pouet.net можно указать HTTP-прокси (`proxy_ip`,
  `proxy_port` в `zifi.ini`). При старте выводится, включён прокси, выключен
  или недоступен.

### Проверка скачанного

- Если сервер назвал `Content-Length`, файл принимается только при точном
  совпадении длины. Обрыв связи даёт ошибку, а не обрезанный файл.
- Файл `.zip` обязан начинаться с сигнатуры ZIP, поэтому страница ошибки
  PHP/HTML или ответ прокси не запишется на SD под видом архива.
- Превышение буфера загрузки 640 КиБ — явная ошибка.

## zifi.ini

Файл кладётся на SD-карту в `/zifi/zifi.ini`. В git он не хранится
(`.gitignore`), потому что содержит пароль Wi-Fi. Строки, начинающиеся с `;`, —
комментарии.

```ini
SSID: Your_WiFi_Network
password: Your_WiFi_Password
; Часовой пояс: смещение от UTC (от -14 до +14) или none — часы не трогать
time: +2
; Необязательный HTTP-прокси для vtrd.in, zxart.ee, pouet.net
proxy_ip: <адрес>
proxy_port: <порт>
```

## Сборка

Нужны `sjasmplus` и драйвер FAT32, клонированный рядом с этим репозиторием:

```
git clone https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution.git "FAT32 Driver"
```

`build.bat` собирает драйвер, затем `zifi.asm` (общие исходники берутся из
`shared/z80`) и упаковывает `build/zifi.spg` программой `_spg/spgbld.exe` по
`_spg/spgbld.ini`. `zifi.asm` даёт два блока: `build/zifi.bin` — сама программа и
`build/zifi_win.bin` — окна сообщений и код сохранения на SD, которые кладутся в
страницу `#11`; драйвер — `build/fat32.bin` (страница `#0E`) и
`build/fat32-work.bin` (`#0F`).
Путь к `sjasmplus` задаёт переменная `SJASMPLUS`, путь к драйверу —
`FAT32_DRIVER_DIR`.
