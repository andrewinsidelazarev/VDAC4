# Самостоятельный FAT32

`zifi.spg` использует драйвер из отдельного репозитория
[FAT32-Driver-ZX-Evolution](https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution)
(лицензия MIT), версия от 2026-10-07 (`e728390`). Его клонируют рядом с этим
репозиторием, в папку `FAT32 Driver`:

```
git clone https://github.com/andrewinsidelazarev/FAT32-Driver-ZX-Evolution.git "FAT32 Driver"
```

От `ZiFi SPG` это путь `../../FAT32 Driver`; другой путь задаётся переменной
`FAT32_DRIVER_DIR`. Сборка `build.bat` сначала собирает драйвер, затем
включает его код на страницу `#0E`, рабочую RAM (с кодом `safety.asm` и SD-ZC) —
на `#0F`; `fat32-work.bin` загружается целиком.

## Где что

- `fat32_adapter.asm` (страница программы): вход в драйвер с сохранением банков
  0, 1, 3 и режима прерываний, чтение `zifi.ini`, дозапись загрузки APPEND
  частями по страницам 16 КиБ с проверкой границ 640-КиБ буфера.
- `fat32_window.asm` (страница окон `#11`, окно `#C000`): имя файла по правилам
  драйвера, временный файл, подмена FILEX MOVE, время файла FILEX
  SET_METADATA, каталоги загрузок. Вызов — `win_call` (лежит в странице
  программы перед `mouse_step`, переходом на `win_call_guarded`) с разрешёнными
  прерываниями: под прежним DI на всё время поиска и подмены файла терялись
  растровые прерывания и после загрузки мигали оба экрана; обработчики интерфейса
  (`save_mode`) и музыка (`music_sw`) на это время выключены; блок параметров
  FILEX там же (`fat_filex_block`): драйвер принимает его только в
  `#8000..#BFFF`.

## Сохранение

1. `fat_prepare_target`: цель — каталог или файл «только для чтения» — отказ
   (`#1A`, `#18`). Остаток прошлой попытки `имя.$$$` удаляется, если его цепочка
   не общая с целью (общая — `#20`, том не трогается). Создаётся новый
   `имя.$$$`. Скачанное имя с окончанием `.$$$` заранее становится `…_$$$`,
   чтобы не совпасть с временным.
2. APPEND частями, CLOSE.
3. `fat_commit_replace`: FILEX MOVE с заменой `имя.$$$` → `имя`. Статус
   COMMITTED_CLEANUP (перенос лёг, прежняя цепочка не освободилась) — успех:
   файл целый, на томе потерянные кластеры.
4. FIND и FILEX SET_METADATA: время создания, изменения и доступа по часам
   Evo (см. README, «Время файла»).

Ошибка — окно «SD save failed; file may be partial» с кодом драйвера или
статусом FILEX.

## Проверка

- `tests/test_zifi_spg_fat32.py`: собранные `zifi.bin`, `zifi_win.bin`, драйвер и
  SD-ZC исполняются на модели SD-карты драйвера (CRC16, CMD13), подменены только
  интерфейс, окно ошибки и часы CMOS. Независимый разбор тома после каждого
  сценария: все каталоги, LFN, цепочки, перекрёстные ссылки, потерянные
  кластеры, размеры, «.» и «..», зеркала FAT, FSInfo. Сценарии: размеры
  0…640 КиБ, замена, 240 сохранений в одном каталоге, заполнение тома, имена
  (и окончание `.$$$`), online-unzip, часы (BCD, двоичные, 12-часовые, сбитые,
  полночь между чтениями), прерывание музыки посреди передачи сектора — только
  при IFF1=1, со слежением за стеком и вектором IM2. Перебор на каждой записи
  сектора: отказ (карта сектор не приняла либо приняла и ответила ошибкой) и
  обрыв питания (новый файл и замена, корень и каталог даты, кластеры 512 Б и
  4 КиБ); ошибка чтения на каждом чтении. Цель всегда прежняя или новая
  целиком. Сам fsck проверен на намеренно испорченных томах.
  Нужен пакет `z80` (`requirements-test.txt` драйвера) и свежая сборка.
- Сквозная проверка сборки VDAC4 в Unreal с исправленной моделью SD
  (`TSdCard::Wr`, находка драйвера): режим `TS_ZIFI32=VDAC4`, ESP —
  `tools/unreal/vdac4_esp_host` с сетью zifi.spg, тело отдаёт локальный
  HTTP-сервер. Старт как на плате (`WIFI_INI`, NTP, запись часов, каталог
  даты), загрузки задаются, как из меню: HTTP → ESP → SPI → Z80 → FAT32 →
  образ SD. Файлы до 640 КиБ, online-unzip, музыкальный буфер, замена; образ
  сверен побайтно, по времени файлов и разбором тома.

## Границы

FAT32 не ведёт журнала. После обрыва питания посреди загрузки возможны
потерянные кластеры недописанного файла, устаревший FSInfo и отставшая вторая
копия FAT; в окне подмены — общая цепочка цели и `имя.$$$` (повтор отвечает
`#20`). Всё это chkdsk чинит без потери данных. Проверка на физическом
ZX-Evolution остаётся следующим этапом.
