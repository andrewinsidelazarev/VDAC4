# VDAC4 Online Update 2: устройство (рабочая спецификация, 10.11.2026)

Плагин `VDAC4UPD.WMF` («VDAC4 Online Update») из Wild Commander обновляет с GitHub всё, что стоит на
плате VDAC4: прошивку ESP, прошивку BL616, слоты 0/1/3 flash ПЛИС Tang, папку `CORES` на microSD Tang,
плагины VDAC4 в `/WC` и модули ESP в `/WC/ESP` на карте Evo. Прежний плагин (только ESP) заменяется этим;
имя файла и строка в `wc.ini` те же.

Принцип — как у прежнего Online Update и у ZiFi Online Update: читает и проверяет всё ESP, Z80 показывает
и подтверждает; запрет понижения версии; что не сошлось — не ставится, прежнее остаётся. Как у WC Update:
эталон — хэши git одного коммита ветки `main` репозитория `andrewinsidelazarev/VDAC4`, каждый файл
сверяется по содержимому, список с отметками.

## 1. Эталон: один коммит, одно дерево

1. `GET api.github.com/repos/andrewinsidelazarev/VDAC4/git/ref/heads/main` → коммит.
2. `GET api.github.com/repos/andrewinsidelazarev/VDAC4/git/trees/{commit}?recursive=1` → дерево всего
   репозитория (сейчас ~3600 записей, ~1 МБ JSON, самый длинный путь 109 байт). Берутся только пути из
   правил раздела 2; остальные записи пропускаются, не занимая таблицы. `truncated: true`, испорченный
   JSON, нет обязательного файла (ESP, BL616, слоты) — отказ целиком с текстом.
3. Файлы — с `raw.githubusercontent.com/andrewinsidelazarev/VDAC4/{commit}/{путь}` (части пути — с
   %-заменами, пробелы есть). Каждый скачанный файл сверяется с git-SHA-1 из дерева
   (`SHA1("blob <size>\0" + данные)`), иначе до трёх попыток, затем отказ строки.

Два запроса к API на проверку (GitHub без входа даёт 60 в час); 403/429 — `GitHub API limit`.

## 2. Правила: что, откуда, куда

| Вид | Путь в репозитории | Цель | «Что стоит сейчас» | Версии для показа |
|---|---|---|---|---|
| 1 ESP | `ESP32 S3 Zero N8R8/Firmware/firmware/vdac4/firmware.bin` | раздел OTA ESP | SHA-256 первых `size` байтов работающего раздела приложения против SHA-256 `firmware.bin` из `firmware.sha256` | текущая — версия сборки (`vdac4-X.Y.Z`); доступная — строка `VERSION` из `firmware.sha256` |
| 2 BL616 | `Tang Nano 20k/BL616/firmware/vdac4_copro_bl616.bin` | flash BL616 с 0x40000 (`bl616::push`) | номер прошивки из `CP_INFO` (регистр LINK 0x30, биты 23:16) против последнего `#define FW_VERSION` в `Tang Nano 20k/BL616/app/main.c` | номера |
| 3 Слот ПЛИС | `Tang Nano 20k/Firmware/firmware/ts_fb_hdmi_top.bin` → слот 0; `ts_fb_slot1.bin` → слот 1; `ts_fb_video.bin` → слот 3 | flash Tang `slot × 0x100000` | git-SHA-1 первых `size` байтов слота (`tang_flash::read`) против SHA из дерева | доступная — колонка версии таблицы слотов `Tang Nano 20k/Firmware/README.md` (как `Flasher/src/Manifest.cs`); текущая — у слота 0 из `VERSION` (LINK 0x04, работает TS-Config), у прочих — доступная, если совпало, иначе `?` |
| 4 Карта Tang | каждый файл прямо в `Tang Nano 20k/Cores/SD/CORES/` | `/CORES/<имя>` на microSD Tang | git-SHA-1 файла на карте | размер, КБ |
| 5 Карта Evo | `ESP32 S3 Zero N8R8/Network/*/build/vdac4/*.WMF`, `ESP32 S3 Zero N8R8/Network/VDAC4 VFS/build/*.WMF`, `ESP32 S3 Zero N8R8/Sound/MP3 Player/build/VDAC4MP3.WMF`, `Tang Nano 20k/FTVIEW4/build/FTVIEW4.WMF` | `/WC/<имя>` | git-SHA-1 файла на карте (VFS через Z80, как WC Update) | размер, КБ |
| 5 Карта Evo | `ESP32 S3 Zero N8R8/Sound/modules/out/*.ELF`, `ESP32 S3 Zero N8R8/Sound/modules/out/SIDLEN.BIN`, `Tang Nano 20k/Cores/VIDEO/esp/dist/VIDEO.ELF` | `/WC/ESP/<имя>` | то же | размер, КБ |

Не трогаются: `Tang Nano 20k/Cores/SD/AMIGA/*` (дискета пользователя), всё прочее на картах, шрифты
FT812 (слот 2), раздел настроек Tang (0x7F0000), ROM Kickstart. Пути карты Evo — от корня тома, где
найден `/zifi/zifi.ini` (как у WC Update).

## 3. Состояния строки

Номера — как `WcStatus` WC Update, плюс 10:

| № | Состояние | Можно ставить |
|---|---|---|
| 0 | unknown (ещё не проверено) | нет |
| 1 | same | да — переустановка, без отметки по умолчанию |
| 2 | DIFFERS | да, отмечена по умолчанию |
| 3 | NEW (на карте нет) | да, без отметки по умолчанию (новый плагин ещё вписывать в `wc.ini`) |
| 7 | READ ERR (не прочиталось, нет связи с Tang и т. п.; причина — в событии состояния) | нет |
| 8 | UPDATED | — |
| 9 | FAILED (прежнее цело) | да, повтор |
| 10 | OLDER: опубликованная старше стоящей (ESP, BL616) — понижение запрещено | нет |

## 4. Протокол Z80 ↔ ESP

Новые команды (свободные коды):

| CMD → ответ | Данные | Что делает |
|---|---|---|
| `1A` VUP_START → `FE`, затем `9A [1/0]` | `[флаги]`: бит 0 — проверять и карту Evo (вид 5; без него VFS не нужен) | как `WCU_START`: останавливает FTP/SMB/прежний сеанс, требует Wi-Fi, запускает задачу ядра 0; дальше события |
| `1B` VUP_APPLY → `FE`, затем `9B [1/0]` | номера строк по байту | ставит отмеченное в порядке раздела 5 |
| `1C` VUP_STOP → `FE`, затем `9C [1 — остановлена / 0 — ещё работает]` | — | как `WCU_STOP` |
| `1D` VUP_SYNC → `FE`, затем `9D [1]` | — | весь список и последнее состояние заново |

События — те же коды, что у WC Update (сеанс один):

- `67` состояние: `[этап][текущий LE16][всего LE16][проценты][текст, 0]`; этапы: 1 GitHub, 2 опись
  (ESP, BL616, flash, карты), 3 сверка, 4 готово (текущий — сколько можно поставить), 5 установка,
  6 метка SYNC, 7 — ESP поставила свою прошивку и сейчас перезапустится (текст — новая версия), `FF`
  ошибка. После этапа 7 плагин ждёт `READY`, заново поднимает Wi-Fi и шлёт `VUP_START` — новый список
  уже с новой прошивкой.
- `68` строка: `[номер][состояние][флаги][вид][текущее, 0][доступное, 0][имя, 0]`, всего ≤ 63 байт:
  текущее и доступное — до 11 знаков, имя — до 30 (длиннее — его хвост: имя файла в конце пути важнее начала).
  Флаги: 1 — есть на GitHub, 2 — есть на месте, 8 — можно ставить, 16 — отметить по умолчанию (отличается или новый),
  32 — после установки ESP перезапустится. Имя: `ESP32-S3 firmware`, `BL616 firmware`,
  `FPGA slot 0 TS-Config`, `FPGA slot 1 FT812`, `FPGA slot 3 video`, `Tang SD: CORES/NES.BIN`,
  `WC/VDAC4MP3.WMF`, `WC/ESP/PLAYER.ELF`.

Порядок строк: ESP, BL616, слоты 0, 1, 3, затем карта Tang, затем карта Evo (по имени).

## 5. Установка (VUP_APPLY)

Порядок — от безопасного к рискованному, ESP последней (она перезапускается):

1. Карта Evo — механизм WC Update: временный файл, обратное чтение, замена с откатом.
2. Карта Tang — `/CORES/<имя>.tmp`, обратное чтение и SHA, затем замена (как `SDPUT`). Только при
   TS-Config 1.30+ и карте, не отданной WC (SD2).
3. BL616 — скачать, сверить git-SHA, `bl616::checkImage`, `bl616::push` (ядро Tang 1.8+); новый
   `CP_INFO` → текущая версия строки.
4. Слоты ПЛИС 1, 3, затем 0 — скачать в PSRAM, сверить git-SHA, проверка A5C3 и IDCODE 081B, стереть
   блоки слота, записать, прочитать обратно и сравнить (как `BEGIN` службы 8268). Только когда работает
   TS-Config (личность 01) и мост flash отвечает. Слот 0 — последним из слотов: новый TS-Config
   загрузится при следующем включении.
5. ESP — как прежний Online Update: `firmware.sha256` заново, `firmware.bin` в свободный раздел OTA с
   проверкой заголовка и SHA-256. Перед перезапуском — строка ESP (`UPDATED`) и событие `67` этапа 7
   (текст — новая версия), около секунды на доставку (очередь событий, опрос Z80 раз в кадр); затем ESP перезапускается, плагин ждёт `READY` и
   проверяет всё заново. Не сошлось — строка `FAILED`, этап 4, прежняя прошивка работает.

Запрет понижения: строки 10 (OLDER) не ставятся, и ESP проверяет это сама, а не только плагин.
Любой сбой строки — `FAILED` с причиной, остальные строки продолжаются (кроме случаев «проверьте
карту», как у WC Update). Esc в плагине до Enter — выход без изменений; во время установки — `VUP_STOP`
после текущей строки.

## 6. Пределы и память

- Дерево до 2 МБ JSON в PSRAM; строк в таблице до 96.
- Файл/образ целиком в PSRAM до 2 МБ (ядро .BIN 907 418 Б); ESP — потоком (как сейчас).
- Задача `vdac4-update`: стек 16 КБ (TLS), ядро 0; перед стартом плагин шлёт `SYS_RESET` и ждёт `READY`
  (как прежний Online Update), чтобы освободить кучу.
- Время на плате (оценка): дерево ~5 с; чтение трёх слотов flash ~?; хэш `CORES` (5 × 0,9 МБ) ~?.

## 7. Проверки

- ESP: стенд ПК по образцу `tests/test_wc_update_host.py` (`tools/host_wcu`): «GitHub» из папки (дерево,
  raw), модель Tang (flash, `CP_INFO`, `VERSION`, карта Tang), модель BL616 push, модель VFS карты Evo;
  сценарии: всё совпало, отличается каждый вид, новый файл, понижение запрещено, испорченная загрузка,
  обрыв, нет Tang, лимит API, STOP.
- Z80: модель плагина на стенде SPI (`Network/tests`, по образцу `test_cores_plugin_z80.py`): список,
  отметки, Enter, ожидание `READY` после перезапуска ESP, VFS для карты Evo.
- Плата — по слову пользователя.
