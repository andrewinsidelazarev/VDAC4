# FTP-сервер для ZX Evolution с платой VDAC4

Прошивка ESP32-S3 платы VDAC4 и плагин `VDAC4FTP.WMF` вместе дают ZX Evolution
с TS-Config и Wild Commander FTP-доступ к SD-карте по локальной сети: просмотр
каталогов, скачивание и загрузка файлов, создание папок, переименование и
удаление. Сервер принимает до трёх управляющих сессий: в FileZilla и WinSCP не
нужно ограничивать число соединений.

Работа разделена так, чтобы Z80 не занимался тем, что ему тяжело:

- **ядро 0 ESP32-S3** держит Wi-Fi, TCP и весь протокол FTP;
- **ядро 1 ESP32-S3** обслуживает канал SPI с Z80 и VFS-клиент;
- **Z80** обслуживает только файловые запросы через DOS API Wild Commander;
- между ними — двоичный протокол ZiFi по SPI платы Evo (порты `#57`/`#77`).

Корень FTP `/` совпадает с корнем выбранной SD-карты. Все файловые операции
выполняются встроенным FAT-драйвером Wild Commander; плагин не обращается к
SD-контроллеру напрямую.

Между сетью и каналом SPI находятся два SPSC-кольца по 64 КиБ в PSRAM. Они позволяют
сетевому ядру продолжать приём, пока Z80 пишет SD-карту, и передавать файловые
данные окнами до 16 КиБ без отдельной копии целого окна во внутренней RAM.

## 📡 Описание протокола ZX ↔ ESP

**[Описание протокола](../../Docs/PROTOCOL.md) — двоичный API между Z80 и ESP32-S3.**

Это самостоятельная часть проекта: протокол не завязан на FTP и годится для
любой задачи, где Спектруму нужен сетевой сопроцессор. В документе — формат
пакета, все команды в обе стороны, файловые приказы ESP → Z80, правила
готовности и то, что определяет скорость обмена.

## Готовые файлы

Плагин находится в `build/vdac4/VDAC4FTP.WMF`, прошивка платы — в
`../../Firmware/firmware/vdac4/` (см. [README прошивки](../../Firmware/README.md)).

Даты файлов (см. [ниже](#даты-файлов)) требуют
[Wild Commander Improved v1.11i от 28 сентября 2026 года](https://github.com/andrewinsidelazarev/Wild-Commander-Improved/releases/tag/v1.11i-2026-09-28) или
новее. Со старым WC сервер работает как прежде, со строкой `Jan 01 00:00` в
листинге.

## Возможности

- запуск из меню плагинов Wild Commander по `F10`;
- чтение настроек Wi-Fi из `/zifi/zifi.ini`;
- подключение ESP к Wi-Fi и ожидание DHCP-адреса;
- показ версии прошивки ESP;
- двоичный протокол Z80 ↔ ESP по SPI, блоки данных — через DMA TS-Config;
- показ уровня Wi-Fi отдельной 16-сегментной шкалой с точным процентом в поле
  `Status`, без вызовов `SYS_INFO` или файловых команд; клетки шкалы и процент
  цветные: зелёные от 60 % (сигнал от −66 дБм), жёлтые от 30 % (от −78 дБм),
  ниже — красные (цвет — плагин v0.15);
- показ IP-адреса и управляющего FTP-порта в отдельных полях;
- доступ на чтение и запись ко всему выбранному тому SD-карты;
- просмотр каталогов и скачивание файлов через `LIST`, `NLST` и `RETR`;
- загрузка файлов на SD через `STOR`;
- русские имена файлов через UTF-8 с преобразованием в кодировку Wild Commander;
- потоковая передача без прежнего предела загрузки 256 КиБ;
- создание каталогов и удаление файлов;
- пассивный FTP через `PASV`/`EPSV`, активный `PORT`/`EPRT` как fallback;
- до трёх управляющих FTP-сессий без настройки клиента «максимум 1 соединение»;
- завершение работы сервера по `Esc`; если FTP-клиент что-то записал, удалил
  или создал, Wild Commander при выходе перечитывает обе панели (как после
  SMB-сервера и UNZIP), иначе панели не трогаются — плагин v0.14;
- даты файлов в листинге (`LIST`, `MLSD`, `MLST`) и `MDTM` — те же, что
  показывает панель Wild Commander, и запись даты командой `MFMT` — плагин
  v0.15;
- окно сервера стоит по центру экрана в любом текстовом режиме WC (80 и 90
  колонок, 25, 30 и 36 строк) — плагин v0.15;
- быстрый листинг каталога: плагин не засыпает (`HALT`) до следующего кадра
  между запросами ESP и отдаёт записи пачками по 16 за один запрос. Прежде
  каждая запись стоила кадр, 20 мс, — папка из 145 файлов листалась 3 с.

## Требования

- ZX Evolution с TS-Config;
- конфигурация TS-Config с ключом `ESP32_SPI` (см. [README](../README.md#что-нужно));
- актуальный Wild Commander Improved с API 76 `APPEND`;
- плата VDAC4 с прошивкой этого репозитория;
- SD-карта, доступная Wild Commander;
- Wi-Fi-сеть, к которой могут одновременно подключиться плата и компьютер с FTP-клиентом;
- обычный FTP-клиент, например FileZilla или `curl`.

> [!WARNING]
> После входа FTP-клиент получает право изменять весь выбранный том: создавать, заменять, переименовывать и удалять файлы. Перед первым испытанием сделайте резервную копию SD-карты.

## Быстрый запуск

1. Соберите проект либо возьмите готовый `build/vdac4/VDAC4FTP.WMF`.
2. Скопируйте `VDAC4FTP.WMF` в каталог `/WC` загрузочного устройства Wild Commander.
3. Добавьте строку `VDAC4FTP.WMF` в секцию `[PLUGINS]` файла `/WC/wc.ini`.
4. Создайте каталог `/zifi` в корне SD-карты.
5. Создайте файл `/zifi/zifi.ini` и укажите в нём имя Wi-Fi-сети и пароль.
6. Запустите Wild Commander, нажмите `F10` и выберите `VDAC4 FTP Server`.
7. Дождитесь шкалы `Wi-Fi [...]` и запишите показанные IP-адрес и порт.
8. Подключитесь к этому IP-адресу и порту FTP-клиентом с обычным пассивным режимом.

Плагин показывает данные `SYS_INFO`, полученные от прошивки. Уровень сигнала
приходит отдельным событием `0x66`, поэтому индикатор не вызывает новый опрос
`SYS_INFO` и не смешивается с системной информацией.

### Прошивка ESP

Первая запись — полный образ `firmware.factory.bin` через USB-C, дальше —
обновление по сети: `../tools/update_vdac4.sna` на Evo открывает порт
обновления, `../tools/esp_tool.py --net <IP>` передаёт `firmware.bin`. Порядок
и ограничения питания — в [README прошивки](../../Firmware/README.md#первая-запись-прошивки).

## Настройка `zifi.ini`

Файл конфигурации должен находиться по пути:

```text
/zifi/zifi.ini
```

Конфигурация:

```ini
SSID: Имя сети
password: Пароль Wi-Fi
```

Для FTP нужны только эти два ключа; `time:` задаёт часовой пояс для дат (см.
[ниже](#даты-файлов)). FTP-сервер всегда использует порт `21`, пользователя
`zx` и пароль `zx`; изменить их через INI нельзя.

Имена ключей не зависят от регистра. Значения разрешается записывать с двойными
кавычками или без них. Поддерживаются окончания строк CR, LF и CRLF, а также
UTF-8 как без BOM, так и с BOM `EF BB BF`. Оба параметра должны полностью
помещаться в первые 511 байт файла.

Готовый шаблон находится в [zifi.ini.example](zifi.ini.example).

### Как выбирается SD-карта

Плагин ищет `/zifi/zifi.ini` в следующем порядке:

1. устройство активной панели Wild Commander;
2. SD1 Z-Controller;
3. SD2 Z-Controller.

FTP открывает корень именно того тома, на котором найден файл конфигурации. Для SD NeoGS каталог `/zifi` должен быть доступен на активной панели в момент запуска плагина.

## Подробная настройка FileZilla

Специальная настройка active mode больше не нужна. Сервер принимает `PASV` и
`EPSV`, открывает для каждой управляющей сессии data-listener на одном из
портов `2122–2124`, а компьютер сам подключается к нему. `PORT` и `EPRT`
сохранены только как запасной вариант.

### 1. Оставьте пассивный режим

Откройте в FileZilla:

```text
Правка → Настройки → Соединение → FTP → Пассивный режим
```

Это стандартный режим FileZilla. Диапазон active-портов на компьютере и
входящее правило брандмауэра для него не требуются.

### 2. Создайте профиль сервера

Откройте `Файл → Менеджер сайтов`, создайте новый сайт и укажите:

| Поле | Значение |
| --- | --- |
| Протокол | `FTP — протокол передачи файлов` |
| Хост | IP, показанный плагином, например `192.168.1.105` |
| Порт | `21` |
| Шифрование | обычный FTP без TLS |
| Тип входа | обычный |
| Пользователь | `zx` |
| Пароль | `zx` |

На вкладке настроек передачи:

1. выберите пассивный режим или оставьте режим по умолчанию;
2. не включайте специальное ограничение количества соединений — сервер
   принимает основной канал FileZilla и дополнительные рабочие подключения.

### 3. Подключитесь и проверьте операции

После подключения правая панель FileZilla должна показать корень SD-карты. Для безопасной проверки:

1. создайте каталог с тестовым именем;
2. загрузите в него небольшой файл;
3. скачайте файл обратно и сравните содержимое;
4. скачайте загруженную копию и сравните её хэш;
5. удалите тестовый файл.

Загрузка выполняется обычным перетаскиванием файла с левой панели FileZilla на правую. Скачивание выполняется в обратном направлении.

## Как работает пассивный FTP

FTP использует два TCP-соединения:

1. компьютер открывает управляющее соединение к ESP на порт `21`;
2. перед выдачей списка или передачей файла клиент посылает `PASV` или `EPSV`;
3. ESP сообщает свободный порт `2122–2124`, и компьютер подключается к нему;
4. после завершения операции data-соединение закрывается, а управляющий канал остаётся активным.

При fallback-командах `PORT`/`EPRT` направление меняется: ESP подключается к
указанному порту компьютера. Этот режим может требовать отдельного входящего
правила брандмауэра на ПК.

## Поддерживаемые FTP-команды

Поддерживаются:

```text
USER PASS QUIT SYST FEAT NOOP
PWD XPWD CWD XCWD CDUP TYPE
PASV EPSV PORT EPRT LIST NLST
MLSD MLST MDTM MFMT
RETR STOR SIZE DELE MKD XMKD OPTS
```

Не поддерживаются:

- `REST` — продолжение прерванной передачи;
- `RNFR`/`RNTO` и `RMD`/`XRMD` — переименование и удаление каталогов;
- другие команды, которым сервер отвечает `502 Command not implemented`.

`FEAT` объявляет `MDTM`, `MFMT` и `MLST type*;size*;modify*;`, поэтому
FileZilla и WinSCP читают каталог машинным `MLSD` с точными датами.

## Даты файлов

Сервер отдаёт ту дату, которую показывает панель Wild Commander, — время
**изменения** файла, а не создания. У файлов, скопированных на SD-карту с ПК,
они разные: Windows ставит время создания на момент копирования.

В FAT время хранится местное — так его пишут и WC по часам CMOS, и Windows.
Протокол FTP в `MDTM`, `MFMT` и `MLSD` требует UTC, поэтому сервер переводит
время по поясу `time:` из `/zifi/zifi.ini` — тому же, по которому ESP сверяет
часы по NTP. Без `time:` пояс считается нулевым.

- `LIST` показывает местное время, как `ls -l`: `Mar 15 14:30` для файлов
  моложе полугода и `Mar 15  2024` для остальных.
- `MLSD`, `MLST` и `MDTM` отдают UTC в виде `YYYYMMDDhhmmss`.
- `MFMT YYYYMMDDhhmmss путь` записывает время изменения в запись каталога WC.
  FileZilla делает это сама после загрузки, если включено «Сохранять время
  изменения переданных файлов». FAT хранит секунды с шагом 2, поэтому ответ
  называет фактически записанное время. Дату раньше 1980 и позже 2107 FAT не
  кодирует — сервер отвечает `501`.

Без `MFMT` новый файл получает время по часам WC в момент записи. Если одна из
сторон старая — плагин, прошивка или WC, — дат нет: листинг показывает
`Jan 01 00:00`, `MDTM` отвечает `550`, а `MFMT` отказывает, не трогая файл.

## Ограничения

### Размер передаваемых файлов

| Направление | Действие пользователя | Ограничение плагина |
| --- | --- | --- |
| С компьютера на SD-карту ZX | загрузка файла на сервер | внутреннего предела 256 КиБ нет |
| С SD-карты ZX на компьютер | скачивание файла с сервера | внутреннего предела 256 КиБ нет |

При `STOR` сетевое ядро непрерывно осушает TCP в 64-КиБ кольцо PSRAM. VFS-ядро
передаёт полное окно 16 КиБ или последний короткий остаток кадрами до
1024 байт. Промежуточных ACK нет: Z80 проверяет sequence, смещения и общий
CRC-16/CCITT-FALSE, затем отвечает один раз на целое окно. Полные 16 КиБ
записываются одним вызовом API 76 `APPEND`; короткий хвост — при
`VFS_CLOSE(commit)`. Максимальное окно занимает 17 кадров.

Пока `APPEND` занят SD-картой, ESP продолжает читать data-сокет в свободное
место кольца; когда кольцо заполнено, TCP штатно создаёт обратное давление.
Индикатор FileZilla показывает сетевую передачу, а не отдельные операции записи
SD. Ответ `226` появляется только после проверки и публикации последнего
остатка. Практический предел задают FAT, свободное место и 32-битный размер
файла.

При `RETR` Z80 читает до 32 секторов (`16 КиБ`) одним `LOAD512` и отправляет
окно кадрами с общей CRC. Прошивка кладёт данные прямо во второе кольцо
PSRAM, откуда сетевое ядро отдаёт их клиенту. Поэтому размер файла внутренним
буфером не ограничен.

Окно 16 КиБ идёт по SPI блоками через DMA TS-Config (см.
[`Docs/VDAC4.md`](../../Docs/VDAC4.md#блоки-через-dma)); скорость задают канал
SPI, запись SD и Wi-Fi. CRC-16 окна плагин считает по таблице (~86 тактов Z80 на
байт).

Замена существующего файла не транзакционная: после начала `STOR` прежнее
содержимое уже удалено. При сетевой или дисковой ошибке плагин пытается удалить
частичную замену, но прежний файл восстановить не может.

### Другие ограничения

- одновременно поддерживаются три управляющие FTP-сессии, поэтому FileZilla и
  WinSCP могут отдельно держать навигацию и рабочие соединения без ограничения
  клиента значением `1`;
- каждой сессии назначается свой passive-порт из диапазона `2122–2124`;
- файловые команды и data-передачи выполняются последовательно через один
  физический VFS-тракт Wild Commander;
- один компонент пути ограничен 63 символами;
- полный путь ограничен 255 символами;
- в именах через FTP поддерживаются ASCII, русский алфавит и `Ё`/`ё`;
  другие символы Unicode отклоняются ответом `501`;
- FTP не шифрует имя пользователя, пароль и данные;
- сервер предназначен только для доверенной локальной сети.

## Диагностика

### Сервер отвечает `425 Passive data connection timed out`

Клиент не подключился к указанному в `227`/`229` data-порту из диапазона
`2122–2124` за 10 секунд. Проверьте, что выбран пассивный режим, компьютер
использует IP и порт из ответа сервера, устройства находятся в одной сети и
между ними нет гостевой изоляции.

### Сервер отвечает `425 Use PASV/EPSV or PORT/EPRT first`

Клиент начал `LIST`, `RETR` или `STOR`, не подготовив data-соединение. Для
обычной работы он должен сначала послать `PASV` или `EPSV`.

### Сервер отвечает `421 Too many FTP sessions (maximum 3)`

Клиент уже занял все три управляющих слота. Закройте лишние вкладки или
оборванные подключения и подключитесь заново. Для обычной навигации и фоновой
передачи ограничивать FTP-клиент одним соединением не требуется.

### Сервер отвечает `530`

Используйте строго пользователя `zx` и пароль `zx`. Эти значения не читаются из
`/zifi/zifi.ini`.

### Сервер отвечает `452 Cannot write file to SD card`

Проверьте свободное место, состояние файловой системы, доступность выбранного тома и корректность имени файла.

### В поле Firmware показано `ESP silent: no SYS_INFO`

ESP ответила `READY`, но не вернула сведения о прошивке. Перезапустите ESP
и проверьте, что прошивка и `VDAC4FTP.WMF` взяты из одного выпуска.

### Плагин не находит конфигурацию

Проверьте точный путь `/zifi/zifi.ini`, наличие обязательных ключей и то, что параметры находятся в первых 511 байтах. Для NeoGS перед запуском откройте нужный том на активной панели Wild Commander.

### IP остаётся `0.0.0.0`

Адрес ещё не выдан DHCP. Проверьте SSID, пароль, уровень сигнала и настройки
DHCP маршрутизатора; `0.0.0.0` считается неготовым адресом.

## Обновление и удаление

Для обновления остановите плагин клавишей `Esc`, замените `/WC/VDAC4FTP.WMF` файлом из нового релиза и снова запустите Wild Commander.

Для удаления:

1. остановите сервер;
2. удалите строку `VDAC4FTP.WMF` из секции `[PLUGINS]` файла `/WC/wc.ini`;
3. удалите `/WC/VDAC4FTP.WMF`;
4. при необходимости удалите `/zifi/zifi.ini`.

## Сборка из исходников

Нужен ассемблер `sjasmplus`. Скрипт ищет его в следующем порядке:

1. путь из переменной среды `SJASMPLUS`;
2. `C:\z80\zuma\sjasmplus.exe`, затем `E:\zx\z80\zuma\sjasmplus.exe`;
3. соседний каталог `..\..\ZiFi\sjasmplus.exe`;
4. команда `sjasmplus.exe` из `PATH`.

Сборка (плагин собирается только для платы VDAC4; так же его собирает
`..\build_vdac4.bat`):

```bat
build.bat
```

```text
build\vdac4\VDAC4FTP.WMF            плагин Wild Commander (хранится в репозитории)
build\vdac4\*.lst, build\vdac4\*.sym   листинги и карты символов (не хранятся)
```

Общие ASM-исходники протокола берутся из `..\shared\z80`. Обновление прошивки
по сети — `..\tools\update_vdac4.sna` и `..\tools\esp_tool.py`. Тест сервера
на ПК (настоящий `ftp_server.cpp` и мост VFS со стендом Wild Commander) —
`..\tests\test_ftp_host.py`.

## Работа с FAT API Wild Commander

Файловая часть использует только API Wild Commander:

- `STREAM` создаёт отдельные потоки корня SD и текущего каталога FTP;
- `FENTRY`, `GDIR`, `ADIR` и `FindNext` работают с каталогами;
- `GFILE` открывает файл, а `LOAD512` читает одним запросом до 32 секторов в
  отдельную 16-КиБ страницу;
- `MKFILE` создаёт файл, а API 76 `APPEND` принимает до 16 КиБ одним вызовом;
- `MKdir`, `REName` и `DelFl` изменяют файловую систему.

Низкоуровневые `IN`, `OUT` и DMA используются только для обмена с ESP по SPI.

## Структура проекта

- `src/main.asm` — заголовок WMF и точка сборки;
- `src/ftp_server.asm` — жизненный цикл окна и сервера;
- `..\shared\z80\zifi_link.asm`, `zifi_spi.asm` — канал SPI с ESP (SPI Slave HD, блоки через DMA);
- `..\shared\z80\proto.asm` — двоичные пакеты Z80 ↔ ESP;
- `src/vfs.asm` — VFS, CRC и 16-КиБ страницы для `LOAD512`/`APPEND`;
- `src/fs.asm` — потоки, пути и кодировка имён;
- `..\shared\z80\config.asm` — чтение `/zifi/zifi.ini` через FAT-драйвер;
- `src/ui.asm` — пользовательский интерфейс плагина;
- `..\src\ftp_server.cpp` — FTP control/data sockets нативной прошивки;
- `..\src\vfs_bridge.cpp` и `..\src\vfs_client.cpp` — межъядерные кольца и
  оконный обмен VFS;
- `build.bat` — сборка;
- `zifi.ini.example` — шаблон конфигурации.

Исходные комментарии и документация сохранены в UTF-8 и написаны по-русски.
