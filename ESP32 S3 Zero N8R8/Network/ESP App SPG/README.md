# ESP App SPG — запускатель приложения ESP

Программа SPG для ZX Evolution (TS-Config) с платой VDAC4: грузит в ESP32-S3 приложение
в формате ELF и запускает его. Исходник один на все приложения: имя, длину и сам ELF
задаёт сборка, своего кода у каждого приложения на Z80 нет. Приложения — демы
[`BOING.ELF`](../../../../demo/boing/README.md) (шарик Boing Ball Amiga на FT812) и
[`DEMO3D.ELF`](../../../../demo/demo3d/README.md) (тор и кубы — 3D-команды сопроцессора BL616).

ELF лежит внутри SPG: загрузчик SPG кладёт его в страницы памяти с `#20`, и искать
файл на карте не нужно. Копия `ИМЯ.ELF`, которую сборка кладёт рядом со `ИМЯ.SPG`, для
запуска не нужна — это тот же файл, например для `/WC/ESP/`.

Приложению со своим ядром ПЛИС (ESP `vdac4-0.1.164`+) ядро кладётся в тот же SPG:
`build.bat ИМЯ.ELF ЯДРО.BIN`. Битстрим (до 1 МБ, с синхрословом Gowin в начале) идёт в
страницы вслед за ELF и уходит в ESP первым — тем же путём, но с флагом 2 в `MOD_QUERY`.
ESP кладёт его на флешку USB (`/cores`) и в следующий раз годную копию с карты не берёт;
грузит ядро в ПЛИС само приложение — `core_load("ЯДРО")` (Docs/VDAC4.md, «кэш ядер ПЛИС с
карты Evo»). ESP не взяла ядро (нет места, плохое имя) — ELF не шлётся, бордюр красный.

Приложению с большими файлами данных (ESP `vdac4-0.1.165`+; у Quake 2 — `PAK0.PAK`, 50–180 МБ)
файлы в SPG не кладутся: они лежат на карте Evo в папке приложения, а сборка знает только их
имена — `build.bat ИМЯ.ELF [ЯДРО.BIN] ДАННЫЕ.EXT …`. Запускатель находит папку, читает файлы
драйвером FAT32. С ESP `vdac4-0.1.167` файлы не передаются вовсе, даже при вставленной флешке:
пока приложение работает, запускатель отдаёт ESP их куски по запросу — раздел
[«Файлы данных»](#файлы-данных) (пользователь 24.11.2026: «И кэш флешки OTG не используем - ждать
полдня на копирование - такое»). `vdac4-0.1.166` делает так только без флешки, а с флешкой, как и
`0.1.165`, сначала копирует файл на неё и в следующий раз файл с карты не берёт.
С `vdac4-0.1.175` ESP при вставленной флешке сначала ищет файл на ней: в
`/SYSTEM/CACHE/ПРИЛОЖЕНИЕ/`, потом во всей `/SYSTEM/CACHE` с вложенными папками (Docs/VDAC4.md).
Нашёлся — читает его оттуда, и запускатель этот файл не отдаёт; нет — как с `0.1.167`, с карты
по запросу. Сама ESP на флешку ничего не копирует: копию туда кладёт пользователь.

Приложению с дополнительными модулями ELF (26.11.2026, для Quake 2: горячий код рендера — модуль
`Q2HOT.ELF`, его приложение грузит `module_open_ex` с `ZM_MODULE_TEXT_INTERNAL` во внутреннее ОЗУ)
модули кладутся в тот же SPG: `build.bat ИМЯ.ELF [ЯДРО.BIN] +МОДУЛЬ.ELF … [ДАННЫЕ.EXT …]` (путь к
модулю — с «+» впереди или просто путь к существующему файлу `.ELF`). Каждый модуль идёт в страницы
вслед за ELF и ядром, со своей страницы, и уходит в ESP после главного ELF, до файлов данных и
`APP_START`, — тем же `MOD_QUERY`/`MOD_PUT`/`MOD_COMMIT` с флагом 0; годная копия в кэше ESP не
передаётся. ESP модуль не взяла (нет места, плохое имя) — следующий модуль, файлы данных и запуск
идут дальше, бордюр не красный: приложение само решает, как жить без модуля (у Quake 2 — свои
копии функций). До 8 модулей, каждый — 8.3 из `A–Z 0–9 _ -`, файл ELF до 2 МБ (больше ESP не берёт).

## Что нужно

- прошивка ESP `vdac4-0.1.76` или новее (ABI модулей 1.3: `ft_open`…`ft_close`); с файлами
  данных — `vdac4-0.1.167`+ (файлы читаются с карты Evo по запросу, флешка не нужна; с
  `0.1.175` файл, найденный на флешке в `/SYSTEM/CACHE`, читается с неё); `vdac4-0.1.166` — то
  же без флешки, с флешкой — долгая копия на неё;
- приложению с FT812 — ядра Tang 1.12 multiboot: слот 0 — TS-Config
  (`fpga/vdac2/out/core_1.12/slot0_ts`), слот 1 — FT812 (`…/slot1_ft`), см.
  [a3-fpga-framebuffer.md](../../../../docs/a3-fpga-framebuffer.md);
- TS-Config с FT812 (бит 2 VCONFIG — изображение FT812, M_SEL).

## Как работает

1. Связь с ESP по SPI платы (общий драйвер [`shared/z80`](../shared/z80)).
2. `MOD_QUERY` с именем, длиной и временем записи ELF: есть такой в кэше ESP — передачи
   нет; иначе ELF уходит кусками по 1016 байт (`MOD_PUT`) и ESP пишет его в свою flash
   (`MOD_COMMIT`, до нескольких секунд). Порядок: ядро ПЛИС (если есть) → ELF → файлы
   данных (если есть; папку и файлы на карте запускатель находит ещё до ядра).
3. Монитор — на FT812: `VCONFIG` = `#04`. Это и есть M_SEL: пока он 1, ядро FT812 в Tang
   не уходит само обратно в TS-Config. Ставится до запуска приложения: приложение само
   переводит Tang в ядро FT812 (multiboot), и без M_SEL ядро через 3 с тишины
   вернулось бы в слот 0.
4. `APP_START` — приложение работает.
5. Любая клавиша — `APP_STOP` (ESP отдаёт FT812 обратно Evo), `VCONFIG` = 0. Через
   3 с Tang сам возвращает ядро TS-Config.

Выход из программы — кнопка Reset, как у `zifi.spg`.

| Бордюр | Что |
|---|---|
| синий | связь с ESP, загрузка ELF |
| зелёный | приложение работает; любая клавиша — стоп |
| чёрный | приложение остановлено, дальше — Reset |
| красный | ошибка: нет ESP, ESP не взяла ELF (нет места, плохое имя), приложение не запустилось; с файлами данных ещё — нет карты, папки или файла, ESP не приняла кусок, файл без флешки раздроблен сильнее 896 кусков |
| голубой и белый попеременно | идёт файл данных (смена цвета — каждые 32 КБ) |
| жёлтый | у ESP нет флешки USB, а прошивка старше `0.1.166` — файлам данных негде лежать (ответ 4) |
| фиолетовый | на флешке ESP нет места под файл данных (ответ 2) |

Зелёный бордюр и чёрный экран — приложение запущено, но не нашло FT812: что именно,
пишет журнал ESP (сетевая консоль, порт 23), у BOING — строка `boing: …`.

## Файлы данных

Для ESP это файлы приложения с карты Evo (Docs/VDAC4.md, «файлы данных приложений с карты
Evo»): `MOD_QUERY` с флагом 4 — `[4][длина LE32][время FAT LE32][ИМЯ.EXT, 0][ПРИЛОЖЕНИЕ, 0]`,
где приложение — имя ELF без `.ELF` (у `Q2.ELF` — `Q2`). ESP держит копию на флешке USB в
`/SYSTEM/CACHE/ПРИЛОЖЕНИЕ/` и отвечает: 0 — годная копия есть (та же длина, не старее файла
на карте) — передачи нет; 1 — шли; 2 — нет места; 3 — плохое имя; 4 — флешки нет (прошивка
`0.1.165`: ошибка с жёлтым бордюром); 5 — файл читается по запросу (ниже: `0.1.166` — без
флешки, `0.1.167`+ — всегда). За именем приложения запускатель ставит номер файла (его место в
`build.bat`) — так прошивка 0.1.166+ узнаёт, что он умеет отдавать файл сам; `0.1.167`+ тогда
флешку не трогает, а не встал файл на учёт — отвечает 3 (красный бордюр). Приложение читает файлы функциями
`data_open`/`data_read`/`data_close` (ABI 1.20) — с флешки или с карты, ему всё равно.

На карту Evo — в одну папку (любую, кроме корня — так у всех программ):

```
ИМЯ.SPG     программа (build\ИМЯ.SPG)
ИМЯ.ELF     копия ELF (build\ИМЯ.ELF) — по ней запускатель узнаёт папку
ДАННЫЕ.EXT  файлы данных, имена — как в build.bat
```

Как запускатель находит папку (`app_dir.asm`, перенесено из DOOM VDAC4):

1. Монтирует первый том FAT32 карты драйвером [`shared/fat32`](../shared/fat32) и спрашивает
   у ESP папку (`PATH_GET`: имя приложения и серийный номер тома — у каждой карты своя
   запись в `path.cfg` ESP). Папка есть и в ней лежат `ИМЯ.ELF` и все файлы данных — берёт её.
2. Иначе — поиск по всей карте: первая папка, где есть `ИМЯ.ELF` и первый файл данных;
   найденную отдаёт ESP (`PATH_SET`), и в следующий раз поиска нет.
3. Записи каталога всех файлов данных: длина, время FAT, первый кластер. Чего-то нет —
   красный бордюр, в ESP ничего не передано.

На карту запускатель ничего не пишет.

Как идёт файл (`app_data.asm`). Файл читается по цепочке кластеров сектор за сектором
(смещение и остаток — 32 бита: файл любой длины до 4 ГБ) порциями по 8 КБ:

- быстрый путь (канал SPI версии 2+ и приём блоков DMA от Z80 — у прошивок с файлами данных
  они есть; проверяется при запуске по байтам 61–62 общего буфера): управляющий
  запрос raw media `[6A][длина LE16][смещение LE32]` и вся порция одной передачей DMA, без
  контрольной суммы — как MP3-плеер отдаёт звук; ответ `EA` ESP шлёт после записи порции на
  флешку, а Z80 тем временем уже читает с карты следующую;
- иначе — кадрами `MOD_PUT` по 1016 байтов с ответом на каждый (около 30 КБ/с).

Скорость быстрого пути (оценка, на плате не измерено): карта — около 60 мс на 8 КБ (Z80 на
14 МГц, драйвер сверяет CRC16 каждого сектора — около 40 тыс. тактов), флешка ESP — около
50 мс на 8 КБ (~170 КБ/с); они идут одновременно, выходит ~125 КБ/с: 50 МБ — около 7 минут,
180 МБ — около 25. Дальше — ответ «есть», передачи нет.

Без флешки (ответ 5, прошивка `0.1.166`+; пользователь 23.11.2026: «Игра должна работать и без
флешки otg esp32»). Файл не передаётся. Запускатель один раз проходит его цепочку FAT и
записывает непрерывные куски — «пробеги» `[первый кластер][кластеров]`, по 8 байтов, в
`#C400`–`#DFFF` страницы `SCRATCH_PAGE` (896 пробегов на все файлы; файл на карту записан
целиком — обычно один-два). Дальше, пока приложение работает (и пока ждёт ответа на
`APP_START`: приложение читает файл уже в `start()`), запускатель опрашивает канал
(`Data_Poll`). Запрос ESP `6E [номер запроса][номер файла][смещение LE32][длина LE16]`
(смещение кратно 512, длина до 32 КБ): по пробегам смещение — сразу в кластер и сектор
(`Data_Seek`), секторы — в порцию 8 КБ, порция — в ESP `6F [номер запроса][смещение][данные]`
быстрым путём (управление 8 байтов, одна передача DMA) или кадрами по 1016 байтов. Ответа ESP
на куски не шлёт. Нет такого файла, смещение за цепочкой, сектор не прочитался — кусок без
данных; ESP спросит снова. Скорость — около 100–125 КБ/с (чтение карты процессором Z80,
оценка): Quake 2 грузит первую карту минуту-полторы, с флешкой — секунды.

Память и страницы:

| Окно | Без файлов данных | С файлами данных |
|---|---|---|
| `#0000` | ПЗУ | ОЗУ (`#21AF` = `#0E`), страница `#0F` — `fat32-work.bin`: буферы драйвера, таблица порта SD с `#3900` |
| `#4000` | страница 5, стек `#5FFF` | страница `#0E` — `fat32.bin`, входы драйвера с `#4000` |
| `#8000` | страница 2 — код и переменные | страница 2 — код и переменные (~7 КБ), стек — под `#C000` |
| `#C000` | страницы ELF и ядра по очереди | они же и рабочая страница `SCRATCH_PAGE` — первая за ELF и ядром: `#C000` — сектор каталога, `#C200` — сектор FAT, `#C400`–`#FFFF` — кадры поиска, потом `#C400`–`#DFFF` — пробеги файлов без флешки, порция 8 КБ — `#E000`–`#FFFF` |

Страницы SPG: 2 — запускатель, `#0E`/`#0F` — драйвер FAT32 (только с файлами данных), с `#20`
— ELF, за ним ядро, за ним модули ELF (каждый — со своей страницы), за ними — рабочая страница
файлов данных. Прерывания всё время закрыты (в окне `#0000` нет ПЗУ), матрица клавиатуры
ZX до запуска приложения не читается. Страницы окон для DMA драйвер канала берёт из своих
ячеек запускателя (`SpgPage2`, `SpgPage3`), а не из ячеек WC `#6002`/`#6003`: там у SPG —
драйвер FAT32.

## Сборка

```powershell
& ".\build.bat"                      # BOING: ..\..\..\..\demo\boing\build\app\BOING.ELF
& ".\build.bat" ..\..\..\..\demo\demo3d\build\app\DEMO3D.ELF   # -> build\DEMO3D.SPG (ELF и SPG сразу — demo\demo3d\build.bat)
& ".\build.bat" путь\к\ИМЯ.ELF       # любое приложение -> build\ИМЯ.SPG
& ".\build.bat" путь\к\ИМЯ.ELF путь\к\ЯДРО.BIN   # приложение со своим ядром ПЛИС в том же SPG
& ".\build.bat" путь\к\Q2.ELF PAK0.PAK PAK1.PAK   # с файлами данных (только имена 8.3)
& ".\build.bat" путь\к\Q2.ELF путь\к\Q2.BIN PAK0.PAK   # ядро и файлы данных
& ".\build.bat" путь\к\Q2.ELF путь\к\Q2.BIN +путь\к\Q2HOT.ELF PAK0.PAK PAK1.PAK   # и модуль ELF
```

Второй аргумент — ядро, если у него расширение `.BIN` и это путь к файлу (файл есть или
указана папка); голое имя без такого файла — уже имя файла данных. Имена файлов данных —
8.3 из `A–Z 0–9 _ -` (до 16 файлов), имя ELF тогда — до 8 таких же знаков.

Нужны sjasmplus (`SJASMPLUS` или `E:\zx\z80\zuma`), Python 3 (`py -3`) и `spgbld.exe` из
[`../ZiFi SPG/_spg`](../ZiFi%20SPG/_spg). С файлами данных `build.bat` сначала собирает
драйвер FAT32 (`../shared/fat32/build.py`). Затем `prep.py` пишет `build/app_cfg.inc`
(имя 8.3, длина, время файла в формате FAT — новый ELF той же длины ESP не спутает со
старым; с файлами данных — их имена, имя приложения, страницы драйвера и рабочая страница),
куски ELF по 16 КБ и `build/spgbld.ini`; затем sjasmplus и spgbld. Без файлов данных
`esp_app.bin` собирается байт в байт таким же, как до них.

| Файл | Что |
|---|---|
| `esp_app.asm` | запускатель (код с `#8000`, страница 2) |
| `app_dir.asm` | папка приложения на карте: `PATH_GET`/`PATH_SET`, поиск по карте (только с файлами данных) |
| `app_data.asm` | файлы данных: `MOD_QUERY` с флагом 4, чтение по кластерам, порции DMA; без флешки — пробеги и куски по запросу ESP (только с файлами данных) |
| `prep.py` | настройка сборки под ELF; с модулями — `build/app_mods.inc` (таблица `ModFiles` для `SendMods`) |
| `build/ИМЯ.SPG` | программа для карты Evo, в любую папку (с файлами данных — рядом с ними) |
| `build/ИМЯ.ELF` | копия ELF |

Тест в эмуляторе Z80 против модели канала SPI и прошивки —
[`../tests/test_esp_app_spg_z80.py`](../tests/test_esp_app_spg_z80.py): ELF доходит до ESP
байт в байт (приложение последней сборки — по `build/app_cfg.inc`), из кэша не передаётся заново, `VCONFIG` `#04` — до `APP_START`, `#00` — после
`APP_STOP`, отказы — красный бордюр. Если последняя сборка — с ядром, ещё: ядро уходит
первым с флагом 2 байт в байт, годная копия у ESP не передаётся, отказ на ядре — ELF не
шлётся (без ядра эти тесты пропускаются). Сборку с файлами данных эти тесты пропускают.

Файлы данных проверяет [`../tests/test_esp_app_spg_data_z80.py`](../tests/test_esp_app_spg_data_z80.py):
свои сборки он делает сам во временной папке (`TEMP`), исполняет запускатель вместе с
настоящим драйвером FAT32 над образом карты (`../tests/fat32_disk.py`). Файл данных доходит
до ESP байт в байт (фрагментированный), у файлов больше 16 и 32 МБ смещения `MOD_PUT`
32-битные и по порядку, порции — по 8 КБ одной передачей DMA (без быстрого пути — кадры по
1016 байтов), ответ 0 — передачи нет, ответы 2 и 4 — свой цвет и нет `APP_START`, отказ на
куске — красный; папка — из `PATH_GET` без поиска, без записи или с негодной — поиском и
`PATH_SET`; порядок ядро → ELF → данные; на карту ничего не пишется. Без флешки
(`EspAppSpgRemoteTest`): ответ 5 — передачи нет, куски по запросу байт в байт (DMA и кадры,
кластеры 512 Б, 4 и 32 КБ, фрагментированный файл, смещения за 32 МБ, через границу кластера,
хвост файла, запрос до ответа на `APP_START`), отказ — кусок без данных, раздроблен сильнее
896 кусков — красный.

```powershell
E:\zx\esp\pio-venv\Scripts\python.exe -m unittest test_esp_app_spg_z80 test_esp_app_spg_data_z80   # из ..\tests
```
