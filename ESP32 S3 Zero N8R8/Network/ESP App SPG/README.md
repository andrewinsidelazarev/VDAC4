# ESP App SPG — запускатель приложения ESP

Программа SPG для ZX Evolution (TS-Config) с платой VDAC4: грузит в ESP32-S3 приложение
в формате ELF и запускает его. Исходник один на все приложения: имя, длину и сам ELF
задаёт сборка, своего кода у каждого приложения на Z80 нет. Приложения — демы
[`BOING.ELF`](../../../../demo/boing/README.md) (шарик Boing Ball Amiga на FT812) и
[`DEMO3D.ELF`](../../../../demo/demo3d/README.md) (тор и кубы — 3D-команды сопроцессора BL616).

ELF лежит внутри SPG: загрузчик SPG кладёт его в страницы памяти с `#20`, и искать
файл на карте не нужно. Копия `ИМЯ.ELF`, которую сборка кладёт рядом со `ИМЯ.SPG`, для
запуска не нужна — это тот же файл, например для `/WC/ESP/`.

## Что нужно

- прошивка ESP `vdac4-0.1.76` или новее (ABI модулей 1.3: `ft_open`…`ft_close`);
- приложению с FT812 — ядра Tang 1.12 multiboot: слот 0 — TS-Config
  (`fpga/vdac2/out/core_1.12/slot0_ts`), слот 1 — FT812 (`…/slot1_ft`), см.
  [a3-fpga-framebuffer.md](../../../../docs/a3-fpga-framebuffer.md);
- TS-Config с FT812 (бит 2 VCONFIG — изображение FT812, M_SEL).

## Как работает

1. Связь с ESP по SPI платы (общий драйвер [`shared/z80`](../shared/z80)).
2. `MOD_QUERY` с именем, длиной и временем записи ELF: есть такой в кэше ESP — передачи
   нет; иначе ELF уходит кусками по 1016 байт (`MOD_PUT`) и ESP пишет его в свою flash
   (`MOD_COMMIT`, до нескольких секунд).
3. Монитор — на FT812: `VCONFIG` = `#04`. Это и есть M_SEL: пока он 1, ядро FT812 в Tang
   не уходит само обратно в TS-Config. Ставится до запуска приложения: приложение само
   переводит Tang в ядро FT812 (multiboot), и без M_SEL ядро через 3 с тишины
   вернулось бы в слот 0.
4. `APP_START` — приложение работает.
5. Любая клавиша — `APP_STOP` (ESP отдаёт FT812 обратно Evo), `VCONFIG` = 0. Через
   3 с Tang сам возвращает ядро TS-Config.

Выход из программы — кнопка Reset, как у `zifi.spg`.

| Бордюр | Что |
|---|---|
| синий | связь с ESP, загрузка ELF |
| зелёный | приложение работает; любая клавиша — стоп |
| чёрный | приложение остановлено, дальше — Reset |
| красный | ошибка: нет ESP, ESP не взяла ELF (нет места, плохое имя), приложение не запустилось |

Зелёный бордюр и чёрный экран — приложение запущено, но не нашло FT812: что именно,
пишет журнал ESP (сетевая консоль, порт 23), у BOING — строка `boing: …`.

## Сборка

```powershell
& ".\build.bat"                      # BOING: ..\..\..\..\demo\boing\build\app\BOING.ELF
& ".\build.bat" ..\..\..\..\demo\demo3d\build\app\DEMO3D.ELF   # -> build\DEMO3D.SPG (ELF и SPG сразу — demo\demo3d\build.bat)
& ".\build.bat" путь\к\ИМЯ.ELF       # любое приложение -> build\ИМЯ.SPG
```

Нужны sjasmplus (`SJASMPLUS` или `E:\zx\z80\zuma`), Python 3 (`py -3`) и `spgbld.exe` из
[`../ZiFi SPG/_spg`](../ZiFi%20SPG/_spg). Сначала `prep.py` пишет `build/app_cfg.inc`
(имя 8.3, длина, время файла в формате FAT — новый ELF той же длины ESP не спутает со
старым), куски ELF по 16 КБ и `build/spgbld.ini`; затем sjasmplus и spgbld.

| Файл | Что |
|---|---|
| `esp_app.asm` | запускатель (код с `#8000`, страница 2) |
| `prep.py` | настройка сборки под ELF |
| `build/ИМЯ.SPG` | программа для карты Evo, в любую папку |
| `build/ИМЯ.ELF` | копия ELF |

Тест в эмуляторе Z80 против модели канала SPI и прошивки —
[`../tests/test_esp_app_spg_z80.py`](../tests/test_esp_app_spg_z80.py): ELF доходит до ESP
байт в байт (приложение последней сборки — по `build/app_cfg.inc`), из кэша не передаётся заново, `VCONFIG` `#04` — до `APP_START`, `#00` — после
`APP_STOP`, отказы — красный бордюр.
