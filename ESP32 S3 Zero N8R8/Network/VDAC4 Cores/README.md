# VDAC4 Cores

`VDAC4COR.WMF` — плагин Wild Commander: ядра ПЛИС Tang Nano 20K платы VDAC4, которых нет во flash
Tang (ZX Spectrum Next, NES и другие), с выбором ядра из списка. Один плагин на все ядра. Сами
ядра, их слои ESP и исходники — [Tang Nano 20k/Cores](../../../Tang%20Nano%2020k/Cores).

## Где лежат ядра

На microSD самой Tang, в папке `\CORES\` в корне карты (кроме неё в корне — только NextZXOS, это её
карта):

| Файл | Что |
|---|---|
| `ИМЯ.BIN` | ядро: двоичный битстрим Gowin с меткой VDAC4 в UserCode (BL616 другие не грузит); имя — до 15 знаков A–Z, 0–9, `_-.` |
| `ИМЯ.ELF` | слой ESP ядра (необязательно): приложение ESP — клавиши, мышь, звук, сеть ядра. Для ZX Next — `NEXT.ELF`. Имя ядра с ELF — до 8 знаков |

Ядра без своего ELF работают с общим слоем прошивки ESP: загрузить ядро, по F12 или при
молчании плагина вернуть Tang в TS-Config; клавиши такому ядру не передаются.

## Как работает

1. Плагин спрашивает у ESP список `\CORES\` (`CORE_LIST`): ESP читает microSD Tang через мост
   ядра TS-Config 1.30. Меню: имя, размер, «own ESP layer» — есть свой ELF.
2. Выбрано ядро — `CORE_APP`: ESP ставит `ИМЯ.ELF` с SD Tang в кэш своих модулей (если файл
   изменился) и запускает его, без ELF — общий слой.
3. `START`: слой грузит ядро в ПЛИС из кэша BL616; ядра в кэше нет или оно на SD новее —
   сначала с SD в кэш (сверка по SHA-256). Плагин ждёт до 180 с, в окне — «Loading ИМЯ…».
   С версии 0.4 Esc с этого шага не выход. Картинка ядра бывает на HDMI раньше, чем плагин
   увидит «работает», а Esc нужен ядру (у ZX Next — BREAK). Загрузку кончает само ядро,
   ошибка слоя или срок.
4. Ядро работает — окно WC закрыто, картинка ядра на HDMI Tang. Раз в кадр плагин передаёт ESP:
   - очередь PS/2 клавиатуры Evo (AVR, регистры Gluk);
   - джойстик Kempston (`#1F`, с 0.9 — все 8 битов: кнопки Sega-пада B/C/A/START, как в R-Type;
     слой Next берёт биты 0…4, NES — все);
   - кнопки и счётчики мыши Kempston (`#FADF`, `#FBDF`, `#FFDF`).

   С версии 0.2 Evo на это время — в режиме FT812: функция WC GVmod (66) с `VCONFIG = #04`
   (M_SEL = 1). Видеошина Evo на IDE-40 молчит, а сброс Evo снимает M_SEL. По этому ядро (Next 0.5+)
   само просит у BL616 возврат в слот 0.

   С версии 0.3 очередь PS/2 на это время читает только плагин: функция WC INT_PL (86) с A' = 2
   выключает разбор PS/2 в прерывании WC, WC включает его сам, когда плагин вернётся. В 0.2
   обработчик прерывания WC (I_N_T → PSD) забирал из очереди по событию клавиши за кадр. Часть
   нажатий и отпусканий не доходила до ядра: клавиша без отпускания залипала, и NextZXOS повторял
   её без конца. Окно ошибки после этого ждёт Esc в самой очереди PS/2.
5. F12 — назад в Wild Commander: ESP возвращает Tang в TS-Config (слот 0), затем плагин
   возвращает текст WC (MNGV_PL 0: режим, смещения, палитра).

## Клавиши

| Клавиша | Действие |
|---|---|
| ↑ / ↓, Enter | выбрать ядро и запустить |
| Esc (в меню и в окне ошибки) | назад в Wild Commander; пока ядро грузится и работает — клавиша ядра |
| F12 (ядро работает) | назад в Wild Commander: Tang — снова TS-Config |
| F1 / F4 / F9 / F10 | у ZX Next — его сбросы и NMI (как в NextNano) |

Если Evo сбросили или выключили, плагин замолкает, и через 1,5 с слой ESP сам возвращает Tang
в слот 0 (сеть его не задерживает). Не вышло — прошивка ESP повторяет BOOT ядру без хозяина
каждые 5 с. Если ESP при этом не работает, вернёт только сброс питания.

## Что нужно

- ядро TS-Config 1.30 в слоте 0 (мост к microSD Tang);
- прошивка BL616 14 (кэш ядер, загрузка по JTAG);
- прошивка ESP `vdac4-0.1.84` (CORE_LIST, CORE_APP, ABI приложений 1.4);
- для ZX Next: `\CORES\NEXT.BIN` и `\CORES\NEXT.ELF` (из `Tang Nano 20k/Cores/SD/CORES`) на
  microSD Tang; NextZXOS — на той же карте.

Окно WC — меню, загрузка ядра и ошибки (нет ESP, нет SD или ядер, слой не запустился, ядро не
загрузилось — с текстом ESP). Из окна ошибки — Esc.

## Установка

`build/vdac4/VDAC4COR.WMF` — в `/WC/` карты Evo, имя — строкой в секцию `[PLUGINS]` файла
`/WC/wc.ini`. Запуск — из меню плагинов (F10): `VDAC4 Cores v0.5`.

## Сборка и проверка

```powershell
& ".\build.bat"
python -m unittest test_cores_plugin_z80   # из ..\tests
```

Тест исполняет плагин в эмуляторе Z80 со стендом канала SPI и моделью ESP: меню (имена, размеры,
свой слой, выбор стрелками, прокрутка), CORE_APP и START — с именем выбранного, окно закрыто,
пока ядро работает, в INPUT — порты Kempston и байты PS/2 по порядку, выход — только по самому
F12, Esc в меню — без запуска, ошибки ESP и отсутствие ESP — окно с текстом, Esc после START —
не выход (0.4: ядро загружается и работает, выход — по F12). С 0.2 — ещё и режим FT812 на время работы ядра (GVmod #04 после закрытия
окна, MNGV_PL 0 после выхода), а при Esc во время загрузки видеорежим не трогается. С 0.3 в
модели WC обработчик прерывания забирает из очереди AVR по событию за кадр, пока плагин не вызовет
INT_PL 2: пока ядро работает, все байты очереди — только в INPUT, ошибка ядра после этого — окно
и выход по Esc из очереди PS/2 (13 тестов; сборка 0.2 на этом стенде теряет и F12).

На плате не проверялся.

## NES: картриджи (плагин 0.5)

Enter/F3 на `.nes` в панели WC загружает файл с карты Evo и запускает NES. Файл передаётся до переключения FPGA, с CRC16 каждого блока и проверкой смещений. При выборе NES в меню F10 открывается браузер карты Tang: Enter — каталог/картридж, PgUp/PgDn — страницы, Esc — родительский каталог и выход из корня. Нужен `CORES/NES.ELF` 0.2; для браузера Tang — ESP 0.1.93 с ABI 1.7. Сами картриджи можно хранить в любом каталоге карты, упаковка в ELF не нужна. F4 сбрасывает NES, F6 переключает пропорции 4:3/16:9 (ядро NES 0.3), F12 возвращает WC. В версии 0.6 добавлены сохранения рядом с исходным ROM на карте Evo или Tang: требуется NES 0.4, NES.ELF 0.3, для записи Tang — ESP 0.1.94. При F12 проверенная временная копия заменяет .sav; при ошибке Enter повторяет запись, Esc явно отказывается от прогресса. Для безопасной замены на Evo нужны FILEX READ_AT, WRITE_AT, MOVE_RENAME и CURRENT_DIR установленного WC. Подробности формата и ограничений — в основном README NES.

В 0.8 — меню F1 ядра NES (NES.ELF 0.5): ESP кладёт запрос в ответ на ВВОД, плагин между кадрами
читает каталог карты Evo (LIST → #6E) или отдаёт образ (READ → #77…#79, отказ #6F).

В 0.9 — снимки F5/F6 ядра NES (NES.ELF 0.6, ядро NES 0.8) для игры с карты Evo: файл `<игра>.sst`
рядом с образом — в каталоге панели, откуда игра запущена, или в каталоге образа из меню F1.
Запросы в ответе на ВВОД: SS_OPEN [длина] — временный `<игра>.sts` (старый временный удаляется);
SS_PUT [смещение][128 байтов][CRC16] — по порядку в сектор, полный сектор — WRITE_AT и чтение
обратно; SS_COMMIT — FILEX MOVE | REPLACE `.sts` → `.sst` (старый снимок цел до замены);
SS_READ — `.sst` прежними #77…#79. Итог — #6F [код]. После OPEN/PUT следующий ВВОД уходит сразу,
без ожидания кадра. Кадры ESP → Z80 — не длиннее 137 байтов. Нужны FILEX READ_AT, WRITE_AT,
MOVE и CURRENT_DIR установленного WC (как для сохранений).

Ассоциация объявлена в заголовке WMF; существующую строку `VDAC4COR.WMF` в `[PLUGINS]` достаточно оставить. После замены WMF нужно перечитать плагины или перезапустить WC. Если плагина в `[PLUGINS]` ещё нет, его нужно добавить. На плате новая версия ещё не проверена.
