# Первая прошивка VDAC4

Программа для Windows 10/11 для первой установки прошивок платы VDAC4 по USB. Она шьёт три части:
модуль ESP32-S3 Zero, BL616 модуля Tang Nano 20K и flash ПЛИС Tang.

- Ничего не нужно ставить: ни Python, ни ESP-IDF, ни Gowin, ни BLFlashCommand.
- Программа — один [`VDAC4Flasher.exe`](VDAC4Flasher.exe) (.NET Framework 4.8, он есть в каждой Windows 10/11):
  скачайте его в любую папку и запустите. Прошивки он сам скачает с GitHub. Как подключать плату по шагам —
  в [`README.txt`](README.txt) и в самом окне программы.
- Рядом с программой появятся папка `firmware` (образы и опись `firmware.ini`) и папка `Backup` (бэкапы).

Дальнейшие обновления идут по сети, из Wild Commander.

**До прошивки — загрузка с GitHub.** При запуске программа качает из репозитория VDAC4 (ветка main) образы
по путям, которые знает сама ([`src/Manifest.cs`](src/Manifest.cs)): ESP `firmware/vdac4/firmware.factory.bin`,
BL616 `Tang Nano 20k/BL616/firmware/vdac4_copro_bl616.bin`, слоты ПЛИС из `Tang Nano 20k/Firmware/firmware`.
- все файлы — с одного коммита: его номер даёт API GitHub, поэтому образы и версии не разойдутся;
- каждый образ сверяется с хэшем git того же коммита (API GitHub отдаёт его в списке каталога), образ ESP —
  ещё и с SHA-256 из `firmware.sha256` рядом с ним;
- версии — из файлов того же коммита: ESP — `VERSION` в `firmware.sha256`, BL616 — `FW_VERSION` в
  `Tang Nano 20k/BL616/app/main.c`, ПЛИС — таблица слотов в `Tang Nano 20k/Firmware/README.md`;
- файлы сначала ложатся в `firmware.download` и переносятся в `firmware` только целиком, сверенными; там
  программа пишет опись `firmware.ini` (суммы, версии, коммит), по ней сверяет файлы и без сети.
  Ошибка загрузки прежний комплект не портит;
- нет связи — можно прошить прежними файлами из `firmware` (окно скажет, что это они), есть кнопка
  «Скачать снова»; API GitHub не ответил (предел запросов) — качается ветка, сверяются SHA-256 образа ESP и
  форматы всех образов.

Описи на GitHub нет, и при пуше новых образов обновлять ничего не нужно. До 10.11.2026 программа брала
опись `Flasher/firmware.ini` с GitHub — папки `Flasher` там не было, и загрузка падала с «GitHub ответил 404».

**Перед записью — бэкап.** Всё, что шаг сотрёт, программа сначала читает с устройства в папку `Backup`
рядом с собой (папку создаёт при запуске, если её нет):
- имя файла — с датой и временем запуска, например `2026-11-07_20-15-03_esp32s3_flash_8M.bin`;
- что где — в `Backup\backup.txt`: файл, адрес, длина, SHA-256;
- прочитанное сверяется (ESP — MD5 самого ПЗУ, BL616 — SHA-256 по XIP), файл после записи читается
  с диска;
- стирать шаг начинает только после того, как бэкап лёг на диск;
- повтор шага не затирает первый бэкап, новый файл получает номер `_2`.

| Шаг | Что подключить | Бэкап и стирание | Как программа пишет |
|---|---|---|---|
| 1. ESP32-S3 Zero | USB к модулю; не отвечает — держать BOOT при подключении | вся flash 8 МБ: прошивка, настройки NVS, LittleFS. Стирается целиком | ПЗУ-загрузчик ESP32-S3 по USB-Serial/JTAG (VID 303A, PID 1001): сброс в загрузчик через DTR/RTS, сжатая запись (zlib), сверка MD5 средствами ПЗУ |
| 2. BL616 | USB к Tang с нажатой UPDATE: COM-порт VID 349B, PID 6160 | раздел прошивки VDAC4 0x40000–0x7FFFF (256 КБ). Стирается целиком; FPGA Partner (0x0) и кэш ядер (с 0x80000) не трогаются | ПЗУ ISP BL616 (bootrom load): образ — с 0x40000, сверка SHA-256 через XIP |
| 3. ПЛИС Tang | USB к Tang без кнопки: USB-JTAG 0403:6010 | отмеченные слоты flash целиком, по 1 МБ: 0, 1, 3 и 2, если пишутся шрифты. Стираются целиком | JTAG через MPSSE (драйвер FTDI `ftd2xx.dll`, Windows ставит его сама): стирание SRAM ПЛИС, мост SPI-flash (инструкция 0x16), запись слотов, сверка чтением, RELOAD |

Бэкап ESP идёт командой ПЗУ READ_FLASH_SLOW — по 64 байта, до 16 запросов в полёте. Так же читает
`esptool --no-stub`. Быстрое чтение (READ_FLASH) есть только у заглушки esptool, а она под GPL.
На плате 8 МБ читаются за 79 с.

Сразу после входа в загрузчик программа выключает сторожевые таймеры RTC ESP32-S3 (RWDT и SWD), как
esptool: сброс через USB-Serial/JTAG их не сбрасывает, и без этого чип перезапускался через ~9 с — на плате
бэкап обрывался на 1 МБ с «Присоединенное к системе устройство не работает». Перед перезапуском в прошивку
снимается флаг «загрузчик принудительно» (RTC_CNTL_OPTION1). BL616 в режиме прошивки Windows показывает
обычным COM-портом «Устройство с последовательным интерфейсом USB» с VID 349B (Bouffalo Lab), PID 6160.

Перед прошивкой плату нужно вынуть из ZX Evolution или выключить Evo: питание Evo и USB одновременно
не включать. Настройки Tang (с 0x7F0000 его flash) программа не трогает. Постоянные ядра три:
TS-Config (слот 0), FT812 (слот 1), видео (слот 3). Шрифты ПЗУ FT812 (слот 2) — данные Bridgetek, в
комплект и на GitHub они не входят. Если положить свой `firmware\tang\romfonts.bin` (VD4FONT1),
программа запишет и его.

## Проверено на плате

10.11.2026, Windows 11, плата VDAC4 вне Evo, прошивки с GitHub (коммит `a433250`: ESP `vdac4-0.1.123`, BL616 41,
ПЛИС 1.46 / 1.45 / 1.43), все три шага подряд:
- ESP32-S3 Zero (COM, 303A:1001): бэкап всей flash 8 МБ за 79 с со сверкой MD5, стирание всей flash, запись
  сжатого образа 2,0 → 1,3 МБ и сверка MD5 — ещё 28 с;
- BL616 (COM, 349B:6160, flash JEDEC C86016, 4 МБ): бэкап раздела 0x40000…0x7FFFF, стирание, запись 240 КБ и
  сверка SHA-256 — 3 с;
- ПЛИС (USB-JTAG Tang, GW2AR-18 IDCODE 0x0000081B, flash 0B4017): бэкап слотов 0, 1, 3, стирание, запись, сверка
  чтением и перезагрузка ПЛИС (Done) — 61 с.
Пользователь: «Работает». После этого в окне поправлена только подсказка шага 2: вместо «найдёт «Bouffalo CDC»» — «найдёт BL616 в режиме прошивки (COM-порт)».

## Файлы

| Файл | Что делает |
|---|---|
| [`src/EspRom.cs`](src/EspRom.cs) | протокол ПЗУ ESP32-S3: SLIP, SYNC, SPI_ATTACH/SET_PARAMS, FLASH_BEGIN (стирание), FLASH_DEFL_*, SPI_FLASH_MD5 |
| [`src/Bl616Isp.cs`](src/Bl616Isp.cs) | ISP ПЗУ BL616: синхронизация 0x55, 0x10, 0x50/0x23, 0x22, 0x3B (4 и 88 байтов), 0x36, 0x30, 0x31, 0x3A, 0x60/0x3E/0x61 |
| [`src/Jtag.cs`](src/Jtag.cs), [`src/Ftd2xx.cs`](src/Ftd2xx.cs) | автомат ТАП и команды MPSSE; FT2232 через `ftd2xx.dll` |
| [`src/Gowin.cs`](src/Gowin.cs) | GW2AR-18: IDCODE, состояние, стирание SRAM, SPI flash через JTAG, перезагрузка |
| [`src/Firmware.cs`](src/Firmware.cs) | образы по описи, проверки: 0xE9 у ESP, BFNP у BL616, A5C3 и IDCODE у ПЛИС, SHA-256, шрифты VD4FONT1 |
| [`src/Manifest.cs`](src/Manifest.cs) | пути образов в репозитории, версии из его файлов, опись `firmware.ini` |
| [`src/Download.cs`](src/Download.cs) | загрузка комплекта с GitHub: номер коммита и хэши git (API), образы, сверка, перенос в `firmware` |
| [`src/Backup.cs`](src/Backup.cs) | бэкап в папку `Backup`: файлы с датой, `backup.txt`, сверка записанного |
| [`src/Wizard.cs`](src/Wizard.cs), [`src/Program.cs`](src/Program.cs) | окно-мастер на русском и английском |
| [`tests`](tests) | проверка на ПК: модели ПЗУ ESP32-S3 (со сторожевыми таймерами и флагом загрузчика, как у чипа), ПЗУ BL616 и FT2232 → ТАП GW2AR → SPI flash (бэкап, стирание, прошивка настоящими образами); загрузка с подменой GitHub (коммит, списки каталогов с хэшами git, raw) |
| [`VDAC4Flasher.exe`](VDAC4Flasher.exe) | готовая программа, собрана из этих исходников; плату 10.11.2026 прошила та же сборка до правки подсказки шага 2 (ниже) |

У прошивки Sipeed FPGA Partner (USB-JTAG в BL616) есть ошибки, openFPGALoader обходит их по
серийному номеру. Здесь они обойдены всегда:
- такты без данных идут командой TMS, а не 0x8E/0x8F;
- данные идут записью с чтением (0x39/0x3B), а не одной записью 0x19.

## Сборка и проверки

Нужен только компилятор C# Roslyn (Visual Studio 2022 Build Tools):

```powershell
.\build.ps1 -Release        # E:\zx\cache\tmp\flasher\build\VDAC4 Flasher — программа и папка firmware
E:\zx\cache\tmp\flasher\build\FlasherTests.exe     # ожидается «ВСЁ ВЕРНО»
E:\zx\cache\tmp\flasher\build\FlasherTests.exe --online     # скачать комплект с настоящего GitHub
```

Папку `firmware` выпуска (образы рабочей копии и опись по ним) собирает `build.ps1 -Release`
(`FlasherTests.exe --make-ini <VDAC4> <файл>`).

`VDAC4Flasher.exe --snapshot <папка>` сохраняет картинки всех страниц окна на обоих языках, а шагов 1–3 — ещё и
«тесно» (`*_crowded.png`: длинная ошибка и открытый журнал): так проверяется, что сообщение не наползает на
полосу хода. `build.ps1 -Release` не удаляет папку выпуска, если в её `Backup` есть файлы.

## Откуда протоколы

- ESP32-S3: [esptool, Serial Protocol](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/advanced-topics/serial-protocol.html).
- BL616: bflb-mcu-tool 1.10 (Bouffalo Lab, MIT) — исходник лежит в `docs/references/flasher-2026-10-27`
  проекта; сверено с журналом записи BLFlashCommand с этой платы.
- Gowin и MPSSE: [openFPGALoader](https://github.com/trabucayre/openFPGALoader) (Apache-2.0) —
  `gowin.cpp`, `jtag.cpp`, `ftdiJtagMPSSE.cpp`, `spiFlash.cpp`.
